# Discord ENTAKU Overlay

Discordの通話参加者を司会席付きのカプセル型テーブルに配置し、発話に合わせて映像を切り替えるOBS用ローカルアプリです。Bun＋TypeScript＋Three.jsで実装しています。

**0.1.0-rc.13（リリース候補）**。実Discord認可・OBS本体での受け入れ、長時間運転、署名、StreamKit互換認証の公開配布条件の確認は完了していません。安定版としては扱いません。

## RC.13の修正

IPCのPINGを正しいJSON文字列にし、認可待機中の通信エラーを利用者の認可拒否と区別します。要求権限はrpcとrpc.voice.readのままです。安全な接続診断はENTAKU_RPC_TRACE=1で有効になります。

インポートしたunlit素材をスタジオの露出から分離し、低露出時のロゴ黒化を修正しました。BLEND材質は表示の滑らかな縁を保ち、PCF影だけをアルファ輪郭に切り抜きます。背景の色調整・Bloom・DoFとアバター除外は維持します。

原因、制限、確認範囲は[認可・ロゴ・透過影](docs/rc13-auth-and-studio.md)を参照してください。実Discordでの認可完了や、添付スタジオ全体の画面確認まで成功したという報告ではありません。

## Bunなしで使う

GitHub Actionsからentaku-windows-developmentアーティファクトを取得し、中の配布ZIPをすべて展開します。ENTAKU-Overlay.exeにランタイムとWeb素材を含み、設定・素材は隣のdataフォルダーへ保存します。exeは未署名です。

Start-Demo.cmdまたはexeの通常起動はデモです。人物のマイクボタンで発話を切り替えます。Discord認可は自動では始めません。

実通話にはデモを終了してStart-Live.cmdを実行します。StreamKit互換認証の説明を読み、同意する場合のみ進めてください。これはStreamKitのアプリ識別子・トークン交換先を使う互換経路で、独立して承認されたENTAKUアプリの認証ではありません。音声の受信・録音・文字起こし・ミュート操作はしません。

OBSのブラウザソースは1920×1080を基準に次のURLを設定します。操作ページはカスタムブラウザドックに登録します。どちらもローカル用アクセスキーは不要です。

```text
http://127.0.0.1:31337/overlay
http://127.0.0.1:31337/dock
```

更新時はアプリを終了し、dataをバックアップしてexeを入れ替え、ソースとDockを再読み込みしてください。素材の再インポートは不要です。従来の基本手順は[起動とOBSへの登録](docs/getting-started.md)にも記載しています。

## 席と操作

司会1〜2人を奥の丸み、一般参加者を左右の対面列、余り1人を手前へ置きます。5人でもカプセル型で、増席時は司会側を固定して手前へ伸ばします。退出だけでは縮小しません。予約があれば復帰時に同じ論理席へ戻します。上限は32席です。

参加者の「…」で画像調整、司会指定、席移動を行います。使用中の席への移動は相手との入れ替えです。退出者の予約を解放すると一覧から除きますが、カスタム画像設定は保持します。共同司会の名札は離し、全席の名札を天板内縁へ寄せています。椅子・コップ・卓上モニターは生成しません。

Dock最上段はdata/presets内のJSON一覧です。末尾の「現在の状態を新規プリセットに…」からファイル名を付けて保存します。スタジオ、カメラ、露出、画質、ポスト効果、画像調整、席、自動ON/OFF、外観を保存します。画像とGLB本体はassetsを参照し、同名ファイルを上書きしません。詳細は[プリセットと席](docs/rc12-presets-and-seats.md)を参照してください。

## カメラと発話

話し始めは実発話2.5秒で切替対象になります。無音2.5秒で終了を確定し、そこから5秒待って構図を縮めます。終了だけを理由にした変更は最後のSTOPから最短7.5秒です。再発話で終了待ちを取り消し、短い言い淀みは同じターンとして扱います。無音を発話量へ加えません。

直近10秒の実発話量で主話者を選び、相槌だけの人に留まりにくくします。単独は望遠寄りの肩越し、ワイドは司会正面の低い軸です。司会席の後ろへ回り込みません。人物の撮影範囲、近クリップ、指定障害物に応じて安全な構図へ退避します。

手動撮影は自動ONなら既定10秒でAUTOへ戻り、Dockに残り時間を表示します。固定するときは自動OFFにします。応酬が続く2人の左右分割は任意の実験機能で、初期値はOFFです。短い相槌では分割せず、3人目の継続参加では全景を挟みます。

詳細: [終了確認](docs/rc11-speech-end.md)、[会話の左右分割](docs/rc10-dialogue-split.md)、[撮影軸と主話者](docs/rc9-dialogue-camera.md)。

## スタジオと映像

Dock内でGLB、GLTFと関連ファイル、フォルダー、ZIPを直接読み込みます。解釈にはGLTFLoader・LoadingManager・公式デコーダーを使います。旧シーンの詳細配置やBox3障害物はJSONで維持します。モデル全ポリゴンから撮影経路を自動生成するものではありません。

画像アバターはPNG／静止WebP、顔矩形、倍率・位置、背面画像、撮影範囲を設定できます。発話時の緑色輪郭、Y軸±30度の追従、背面減光に対応します。

自動露出を標準にし、GLB内に照明があれば標準照明を重ねません。人物の色を露出から保護します。MSAA、描画解像度、PCF影、GTAO、SSR、実験的SSGI、彩度・コントラスト、しきい値付きBloom、DoFを設定できます。影は最大8灯、MSAA 2xも選択できますが、実効サンプル数はGPUに依存します。

詳細: [画像](docs/custom-avatars.md)、[スタジオ](docs/studio.md)、[露出](docs/exposure.md)、[画質](docs/quality-and-desk.md)、[ポスト効果](docs/post-effects.md)。

## 診断とVCチャット検証

匿名化した発話メタデータのJSONL記録・再生、診断JSONに対応します。音声やチャット本文を通常の記録へ保存しません。

VCチャットのIPC検証はENTAKU_PROBE_VC_CHAT=1のときだけ有効です。現在の権限のままMESSAGE_CREATEを購読し、失敗しても参加者・音声発話状態の取得を止めません。GET_CHANNELの履歴や購読ACKだけでは成功とせず、同じVCへの別アカウントの新規テスト投稿で判断します。詳細は[Probe](docs/vc-chat-probe.md)と[診断・再生](docs/diagnostics.md)を参照してください。

## 開発と配布

Bun 1.4.4、Three.js 0.187.0を使い、依存はbun.lockで固定します。

```sh
bun install --frozen-lockfile
bun run dev
bun run check
bunx playwright install chromium
bun run test:e2e
bun run build:exe
bun run smoke:exe
bun run package:windows
bun run verify:package
```

Windows ZIPはクリーンなソースから作成します。BUILD-INFO.jsonにコミット、SHA256SUMS.txtに同梱ファイルのハッシュを記録します。Playwrightとフォントファイルは利用者向けexeへ含めません。

サーバーは127.0.0.1限定でHostと操作Originを検査します。同じPCの別プロセスに対するローカル認証は設けません。Discordトークンはメモリのみです。席・画像・プリセットにはDiscord IDが含まれるため、dataや任意のログを公開する前に内容を確認してください。

自動試験は実Discordの認可、OBSのCEF互換性、実GPUの長時間運転・フレームレートを保証しません。仮想時計の長時間試験と実機運転は区別します。詳細は[検証状況](docs/implementation-status.md)、[受け入れ試験](docs/acceptance.md)、[ADR](docs/adr/)に記録しています。
