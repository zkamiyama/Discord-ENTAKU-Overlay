# Discord ENTAKU Overlay

Discordの通話参加者を司会席付きのカプセル型テーブルに配置し、発話に合わせて映像を切り替えるOBS用ローカルアプリです。Bun＋TypeScript＋Three.jsで実装しています。

**0.1.0-rc.10（リリース候補）**。席管理、自動カメラ、画像アバター、スタジオ編集、診断・イベント再生、Windows向け単独exeを実装しました。実Discord通話・OBS本体での受け入れ試験、署名、互換認証経路の公開配布条件の確認は完了していません。安定版としては扱いません。

## Bunを入れずに使う

GitHub Actionsの成功したCI実行から、`entaku-windows-development`アーティファクトを取得します。アーティファクト内の配布ZIPをすべて展開してください。`ENTAKU-Overlay.exe`だけでも標準ページと素材を配信できます。設定とカスタム素材は隣の`data/`へ保存します。

`ENTAKU-Overlay.exe`の通常起動はデモです。開いたDockで「発話 ON」を押すと緑の縁が反応し、継続発話でカメラが切り替わります。Discord認証を自動的に始めることはありません。

Discordへ接続する場合はデモを終了してから`Start-Live.cmd`を起動し、表示される互換認証の説明を読んで承認します。認証にはStreamKitのアプリ識別子とトークン交換先を利用します。独自アプリへの正式な利用承認ではありません。要求するのは`rpc`と`rpc.voice.read`です。音声の受信・録音・文字起こし・ミュート操作はしません。

OBSには、Dockの「OBSブラウザソースのURL」を1920×1080のブラウザソースとして登録します。操作用にはDock URLをカスタムブラウザドックに登録します。ページはそれぞれ`http://127.0.0.1:31337/overlay`と`http://127.0.0.1:31337/dock`です（ポート変更時はポートを読み替えます）。詳細は[起動手順](docs/getting-started.md)を参照してください。

## RC.10: 応酬が続く2人の左右分割

カメラ設定の「応酬が続く2人を自動で左右分割」で有効にします。初期値はOFFです。音声を解析せず、直近10秒の発話量、交代、重なりを使います。開始の確認は2.5秒、終了は5秒待ち、手動操作を優先します。露出は両面で共有し、DoFと向きはそれぞれの人物へ合わせます。詳しくは[会話の左右2分割](docs/rc10-dialogue-split.md)を参照してください。

## RC.9の発話判断と撮影軸

発話開始は合計2.5秒の実発話で切り替え、終了後の構図縮小・無音によるワイド復帰は5秒待ちます。直近10秒の発話時間で主話者を選び、短い相槌で撮影対象を入れ替えません。ワイドは司会正面の軸に固定し、人物・名札・天板を収める距離を求めます。司会席後方へカメラを置かず、ニアクリップは既定0.15m・設定範囲0.02〜1mにしました。

RC.8の手動撮影後10秒の自動復帰、カウントダウン、自動OFFによる固定、数値スライダー、MSAA 2x、影8灯、メニュー分割も含みます。現在の動作は[会話に合わせたカメラ](docs/rc9-dialogue-camera.md)を参照してください。

## RC.8のカメラと操作

RC.8では一律5秒の候補待機を導入しました。この待機規則はRC.9で開始2.5秒・終了5秒へ変更しています。手動撮影は既定10秒で自動へ戻り、Dockに残り時間を表示します。固定するときは自動をOFFにします。ワイドを低くし、人物撮影は望遠寄りの肩越し構図へ変更しました。

設定は画質・ポストエフェクト・スタジオへ分け、数値欄にスライダーを付けました。MSAA 2xと影の最大8灯を追加しています。詳細は[RC.8のカメラと操作](docs/rc8-camera-controls.md)を参照してください。

## RC.7の映像効果と卓上

「画質と卓上」にポストエフェクトのタブを追加しました。彩度・コントラスト、しきい値付きBloom、人物の距離に連動するDoFを設定できます。人物・アイコン・名札の印刷面は既定で除外し、必要なら効果に含められます。初期値は色調整なし・Bloom/DoF無効で、「自然な仕上げ」で控えめな設定をまとめて適用します。

発話の緑色グローは4倍を標準にしました。天板は白い縁をなくし、濃い木目の全面と強めの艶に変更しました。短い名前は字形の伸ばし方を制限し、字間で幅を埋めます。長い名前は省略せずに圧縮します。詳細は[ポストエフェクト](docs/post-effects.md)を参照してください。

## RC.5の机と画質

増席時は司会側の円弧を動かさず、手前へ伸ばします。以前から保存したセッションは、その既存位置を基準に移行します。

Dockの「画質と卓上」からソフトシャドウ、GTAO、SSR、FXAAを選べます。RC.6以降の標準は影とMSAA 4x、高画質はGTAO・SSRと150%描画を使います。人物画像とアイコンは効果の対象外で、机による遮蔽は維持します。名札は台形断面・両面・横幅を使う太字に変更し、コップとモニターを削除しました。詳しくは[画質と机](docs/quality-and-desk.md)を参照してください。

## RC.4の露出変更

自動露出を既定で有効にしました。スタジオと机をAgXで調整し、人物画像・アイコン・発話グロー・名前プレートの色は保ちます。GLB内に照明があれば標準ライトを追加しません。Dockの「露出・照明」でEV補正、現在値での固定、照明の選択ができます。提供されたBlender比較設定（2^0.8÷683）は手動プリセットとして用意しました。詳しくは[露出と照明](docs/exposure.md)を参照してください。

## RC.3の操作変更

参加者の右端に、撮影・デモ発話・メニューのアイコンを表示します。画像の編集、退出・復帰、司会の指定は「参加者メニュー」にまとめました。アイコンには日本語のツールチップが付き、メニューは矢印キーとEscapeでも操作できます。

「司会に指定」は1名の司会を選び直す操作です。「共同司会に追加」で2名にできます。これはアプリ内の配置ロールで、Discordのサーバーロールを自動取得するものではありません。配置は現在人数ではなく退出者を含む予約数を基準に維持します。増席・司会変更時だけ物理位置を組み替え、論理席IDは保持します。

標準スタジオは参考画像の淡い木目、両面の名札と暖色パネルを取り入れたプロシージャルセットです。実写画像・人物・番組ロゴは同梱しません。スタジオ編集の「番組セット」で表示を切り替え、看板のタイトルも変更できます。旧版で保存したシーンにこの設定がなければ、編集画面で有効にしてください。

肩越しの遮蔽判定は顔・撮影範囲・名前プレートと、画像の前後両面・回転範囲から作る近似ボックスを使います。透過ピクセル単位の判定ではないため、透明な余白が広い画像ではカメラが必要以上に高くなることがあります。

## RC.6の描画修正

SSRの反射しない面が変わる不具合を修正し、背景をMSAA付きのまま維持します。MSAA 4xを標準にし、150%・200%の描画解像度を選べます。人物のカメラ追従から時間補間を外しました。実験的なSSGIは画面内の1回の拡散反射を近似し、初期状態は無効です。人物・アイコン・名札の印刷面は露出と画面効果の対象外です。詳細は[画質と机](docs/quality-and-desk.md)を参照してください。

## 開発

固定バージョンはBun 1.4.4、Three.js 0.187.0です。依存は`bun.lock`で固定しています。

```sh
bun install --frozen-lockfile
bun run dev
bun run check
bun run test:e2e
bun run build:exe
bun run smoke:exe
```

E2Eを初めて動かす開発環境では`bunx playwright install chromium`が必要です。Playwrightは利用者向けexeへ含めません。Windows ZIPはクリーンなチェックアウトから作ります。

```sh
bun run build:exe -- --windows
bun run package:windows
```

出力は`dist/Discord-ENTAKU-Overlay-0.1.0-rc.10-windows-x64.zip`とその`.sha256`です。`BUILD-INFO.json`にソースのコミット、`SHA256SUMS.txt`に同梱ファイルのハッシュを記録します。署名済みexeではありません。

## 保存と安全性

サーバーは`127.0.0.1`だけに公開します。`/overlay`と`/dock`は固定URLで、キー入力やローカル用認証ファイルは不要です。Hostを検査し、別Originからの更新要求とWebSocket接続を拒否します。同じPC上の別プロセスへのアクセス制限は設けません。Discordのアクセストークンはメモリ内だけに保持し、Discord側の認可は従来どおり必要です。

`avatars.json`と`scene.json`は保存成功後に映像へ反映します。編集中のプレビューは本番と別です。席は`data/sessions/`、素材は`data/assets/`へ保存します。アプリを停止してから`data/`をバックアップしてください。人に素材を渡す場合は個人情報を除いてください。

## 検証範囲と残る確認

単体・結合テストではIPCの模擬サーバー、席の永続化、発話・カメラ判断、画像・ZIPの検査、設定保存の失敗、匿名化・再生を検証しています。ブラウザ試験では操作から映像までを接続し、背面の減光は実際の画素で比較しています。単独exe試験はPATHが空の一時フォルダーで実行します。

これらは実Discordの認可成功やOBSのCEF環境の互換性を保証する試験ではありません。仮想時計の2時間テストは、実時間2時間のGPU稼働試験とは別です。詳細は[開発・検証状況](docs/implementation-status.md)と[受け入れ試験](docs/acceptance.md)を参照してください。

Three.jsの機能を優先し、GLTFLoader・LoadingManager・公式デコーダー・OrbitControls・Box3等を利用しています。判断は[ADR](docs/adr/)に記録しています。
