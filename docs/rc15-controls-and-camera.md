# Dock・カメラ・画質の調整（RC.15）

## 初期値

新規設定と、各メニューで初期値に戻した場合に使う値を変更しました。保存済みJSONに明示された値は上書きしません。

| 項目 | 初期値 |
|---|---|
| 名札 | 青地・白文字 |
| 発話開始の確認 | 実発話1.5秒 |
| 無音の終了確認 | 2.5秒 |
| 終了後の切替猶予 | 5秒 |
| 主話者の集計期間 | 10秒 |
| 応酬中の左右分割 | ON。隣接席は対象外 |
| ソフトシャドウ | PCF、1024、最大8灯 |
| GTAO・SSR・FXAA | ON |
| 自然な彩度・コントラスト | 1.2・1.1 |
| EV補正 | +0.5 |

影の灯数は上限です。実際に影を作る灯数は、シーン内の対応するライト数までです。SSGI、Bloom、DoFは引き続き初期値OFFです。

既存の設定を新しい初期値にする場合は、カメラ設定の「カメラ設定を初期値に戻す」、画質の「標準」、露出の「自動に戻す」、ポストエフェクトの「初期値に戻す」を使います。名札はスタジオ内の「卓上」で青地・白文字を選びます。画質の初期化は名札の個別設定を変更しません。調整後は新規プリセットへ保存できます。

## Dock

カメラの構図、遷移、判断、主話者、残り時間をプリセット直下の1行にまとめました。長い名前や理由は省略し、ツールチップで確認できます。独立した「カメラの判断」欄は削除しました。

GLB/GLTFとフォルダの読み込みを同じ高さの隣接ボタンにしました。フォルダにはアイコンを付け、チェックボックスを各ラベルの先頭行にそろえました。「写真風」の表記、「今回のBlenderモデルとの比較」、「自然な仕上げ」のボタンと処理は削除しました。

## カメラのタイミングと構図

発話開始、無音の終了確認、その後の切替猶予、主話者の集計期間を、数値とスライダーで変更できます。全てプリセットへ保存します。無音は発話量に加えません。既定では最後のSTOPから2.5秒で終了を確定し、さらに5秒待って構図を縮めます。再発話すれば終了待ちを取り消します。

主話者は指定期間に重なる実発話区間から選びます。最大30秒分を保持するので、集計期間を広げても、その範囲の取得済みデータを使えます。自動分割の開始確認と終了猶予にも、同じ時間設定を適用します。

共同司会は正面向きで横に並べます。通常のアイコンでは中心間隔1.1mとし、大きいカスタム画像では必要な席間隔を確保します。名札は天板の内縁に別々に置きます。共同司会と左右長辺の隣接席は、応酬が続いても左右分割にせず、2人の中央から撮る1カメラの構図を選びます。対向席など離れた2人は引き続き分割対象です。障害物と人物の撮影範囲の検査は維持します。

画角・ワイド高さ・ニアクリップは参照されている設定なので削除せず、変更した時点で現在の構図へ反映するようにしました。手動撮影の残り期限とAUTO/OFF状態は保持します。手動復帰秒数の変更は次の手動撮影から適用します。使われなくなった固定タイマー定数は削除しました。

## 自然な彩度

低彩度の色ほど増加を大きくし、既に鮮やかな色ほど増加を抑える処理に変更しました。1で変更なし、0で無彩色です。色相を保つ方向に彩度を調整し、色域内に収まるよう増加量を制限します。人物のポストエフェクト除外と透明度は維持します。

Photoshopの非公開アルゴリズムを再現したものではなく、肌色専用の保護判定もありません。Three.jsの既存実装を確認した上で、WebGLのShaderPassへ最小限の処理を追加しました。判断の根拠はADR 0020に記載しています。

## VC-CHAT

Feedを作成したアプリ起動時刻を基準に、それ以前の投稿を除外します。起動後に届いた投稿だけが対象です。チャンネル変更やIPC再接続でも基準時刻を更新しません。再同期のGET_CHANNELが返す履歴のうち、起動後のものは補完しますが、起動前の投稿は表示しません。起動前の投稿が後から編集された場合も追加しません。

Dockだけを再読み込みした場合は、現在のメモリ内の投稿を再表示します。アプリを終了すると内容を破棄します。ファイル保存やチャット送信は追加していません。

## 更新と検証

Bun環境ではアプリを停止してmainを更新し、bun install --frozen-lockfileとbun run build:webを実行してから再起動します。OBSのDockとブラウザソースも再読み込みしてください。既存素材の再インポートは不要です。

自動試験では時間の境界、旧設定の復元、席と名札の設置範囲、隣接席の構図、画角の即時反映、彩度の画素、起動前チャットの除外、狭いDockを確認します。配布物のテスト結果は対応するコミットのCIと照合してください。実DiscordとOBSの実GPUによる長時間確認とは区別します。
