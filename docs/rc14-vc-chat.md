# VC-CHAT（RC.14）

## 通常起動で受信する

ライブ接続では、参加中のサーバーVCのチャットを既定で購読します。ENTAKU_PROBE_VC_CHATやENTAKU_RPC_TRACEは不要です。従来の認可方法と要求権限（rpc、rpc.voice.read）は変更していません。2026年11月9日に利用者から提供されたログでは、付与済み権限にmessages.readがあり、本人の新規投稿の受信を確認できました。別アカウントからの受信や全Discord環境の保証を示すものではありません。

更新後は、次の手順で起動します。

```powershell
bun install --frozen-lockfile
bun run build:web
Remove-Item Env:ENTAKU_PROBE_VC_CHAT -ErrorAction SilentlyContinue
Remove-Item Env:ENTAKU_RPC_TRACE -ErrorAction SilentlyContinue
bun run start --live --compat-auth --accept-streamkit-compat
```

環境変数の削除は以前の診断出力を止めるためで、チャット受信の必須手順ではありません。exe版は新しいexeへ入れ替え、Start-Live.cmdで起動してください。OBSのDockと映像ソースは再読み込みします。URLは変わりません。

## Dockの表示

参加者一覧の下にVC-CHAT欄を追加しました。VC名、受信状態、投稿者、時刻、本文を表示します。GET_CHANNELが返した直近の履歴も表示し、新規投稿をリアルタイムで追加します。自分の投稿も表示対象です。履歴の全件取得や追加のメッセージ取得APIは使いません。

MESSAGE_UPDATEとMESSAGE_DELETEも購読し、届いた編集と削除を反映します。補助購読を利用できない場合は、その状態を欄内に表示して新規投稿の受信を続けます。主購読が拒否された場合は固定のエラー名と数値RPCコードを表示し、音声参加者や発話カメラは継続します。

URLはクリックできるテキストとして表示します。画像、リンク先のプレビュー、埋め込みコンテンツは自動取得しません。添付は件数だけ表示し、実ファイルはDiscordで確認します。チャット送信機能はありません。

末尾を表示しているときだけ自動スクロールします。過去の投稿を読んでいる間は位置を保ち、「新着を見る」で末尾へ戻れます。ヘッダーのコピーアイコンは表示中の投稿者・時刻・本文をクリップボードへコピーします。

## 保存範囲とローカル出力

保持するのは現在のVCの最大100件です。容量はメッセージJSON合計256KiBまで、1投稿は先頭4000文字までとし、省略した場合は表示します。VC移動、退出、IPC切断、アプリ終了でメモリ上の内容を消します。再接続後はDiscordが返す履歴から再構成します。Dockだけの再読み込みなら、サーバーのメモリにある内容を再表示します。

本文や投稿者名は、data、プリセット、診断JSON、匿名化された発話記録へ保存しません。チャットはカメラのAppSnapshotと別に配信し、通常のOverlayには送らず、配信映像にも追加しません。通常起動では端末に本文を出しません。従来のProbeを明示的に有効にした場合だけ、診断の端末出力も動作します。

同じPCから現在の表示内容を取り出す場合は、読み取り専用のGET /api/vc-chatを使えます。

```powershell
Invoke-RestMethod http://127.0.0.1:31337/api/vc-chat
```

このAPIもメモリ上の状態を返し、ファイルは作りません。JSONやコピーした本文を外部へ共有する場合は、個人情報が含まれていないか確認してください。

## 検証範囲

模擬IPCで、フラグなしの受信、チャンネル移動、再接続、二重購読の防止、購読拒否でも音声が続くことを試験しました。履歴と新規イベントの競合、重複、編集、削除、容量上限、本文が診断や録画へ入らないことも対象です。ブラウザでは表示、再読み込み、HTMLのテキスト表示、外部自動取得なし、スクロール、狭い幅を確認しました。

ローカルの型検査、単体・結合194件、ブラウザ45件が成功しています。CIは配布対象コミットの結果と対応付けて確認します。

利用者が提供したログによる実受信と、新しいDock機能の自動試験は区別します。新しいUIでの実Discord・OBSの受け入れは利用環境での確認が必要です。
