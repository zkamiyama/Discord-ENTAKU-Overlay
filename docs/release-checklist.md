# 配布候補の確認

このプロジェクトは未署名のリリース候補です。自動テストの成功と、Discord・OBSを組み合わせた配信環境での確認は別に扱います。

## 公開前に確認すること

| 対象 | 確認内容 |
|---|---|
| Discord | 使用したクライアントのバージョン、認可、参加者取得、発話、VC移動、再接続、VC-CHATの受信 |
| OBS | バージョンとGPU、1920×1080のブラウザソース、Dock、透過、単独／2人／分割、カメラ移動 |
| 描画 | ユーザーのGLBとカスタムアバター、影の透過境界、露出、SSR、DoF、資産切替、長時間運転 |
| 保存 | 既存dataのバックアップ、プリセット復元、席予約、更新後の再起動 |
| 配布 | 互換認証を使う条件、第三者ライセンス、署名の有無、ZIPとSHA-256、同梱BUILD-INFOのコミット |

結果には確認したコミットと環境を記載します。投稿本文・Discord ID・トークンを公開レポートへ含めないでください。実施していない項目は未確認として残します。

## 下書きReleaseを作る手順

`.github/workflows/release-draft.yml`は手動実行専用です。実機確認と配布条件を確認した担当者が`accepted`を選び、既存のタグを指定します。タグは`v`＋package.jsonのバージョンで、実行対象コミットと一致する必要があります。ワークフローはタグを作成・移動しません。

Linuxで型検査・単体／結合・全ブラウザ試験を実施し、Windowsでも型検査・単体／結合・配布ZIP検証・単独起動を行ってから、ZIPとチェックサムを添えた**未公開のプレリリース下書き**を作ります。CIの実行だけで一般公開されることはありません。公開判断は結果と条件を確認した担当者が行います。

現在のCIアーティファクト配布も維持します。このリファクタリング作業では、公開用タグの作成、下書きワークフローの実行、Releaseの公開は行っていません。
