# 起動とOBSへの登録

対象は0.1.0-rc.15、Windows x64のリリース候補です。実通話とOBS本体での受け入れ試験は未完了です。最初は配信せずにプレビューで確認してください。

## 1. ZIPを展開する

配布ZIPを、書き込み可能なフォルダーへすべて展開します。Bun、Node.js、Pythonの導入は不要です。フォントはOSのものを使います。exeは未署名です。OSの保護機能を無効にする操作は案内していません。

`Start-Demo.cmd`または`ENTAKU-Overlay.exe`を起動すると、デモ用の操作ページが開きます。`Start-Demo.cmd`は起動失敗時にコンソールを残します。開かない場合はコンソールの`Dock:`のURLをブラウザに貼り付けてください。起動したコンソールは開いたままにします。

## 2. デモで動作を確認する

人物のマイクアイコン（「発話 ON」）を押すと縁が緑に光ります。話し始めから既定で合計1.5秒の実発話で切替対象になります。無音2.5秒で発話終了を確定し、2人構図から1人へ戻るときや無音によるワイド復帰は、そこから5秒待ちます。終了だけを理由にした構図変更は最後のSTOPから最短7.5秒です。2.5秒未満で再発話すれば同じ発話ターンを再開し、終了確認後でも再発話すれば終了待ちを取り消します。直近10秒の発話時間が主話者の判断に使われます。通信断と机の再配置中は安全なワイドへ退避します。

参加者の「…」メニューから「退出」を選んでも席は残ります。「復帰」は同じ席IDへ戻します。「席予約をリセット」は現在の参加者で配置を作り直す操作です。人数や画像の幅が増えた場合は机を拡げます。単純な退出や画像の縮小では机を縮めません。

## 3. Discordへ接続する

デモをCtrl+Cで終了し、`Start-Live.cmd`を起動します。StreamKit互換認証の説明に同意する場合だけYを選択します。Discord側にStreamKitとして認可画面が出る場合があります。独立して承認されたENTAKUアプリの認証ではありません。

コマンドから起動する場合は次のとおりです。

```powershell
.\ENTAKU-Overlay.exe --live --compat-auth --accept-streamkit-compat
```

音声そのものは受信・記録しません。参加者・発話開始終了と、参加中VCのテキストチャットを読み取ります。チャット本文はメモリ内にだけ保持します。認可を拒否した場合は再認可を繰り返さず、Dockへ状態を表示します。必要なときだけ「再認証・再接続」を押します。

## 4. OBSの二つのページを登録する

OBSのブラウザソースに、Dockの「OBSブラウザソースのURL」を設定します。幅1920、高さ1080を基準にします。透明な背景へ円卓と人物が表示されます。スタジオを追加した場合はその背景も描画します。

OBSのカスタムブラウザドックには、コンソールのDock URLを設定します。表示ページは`http://127.0.0.1:31337/overlay`、操作ページは`http://127.0.0.1:31337/dock`です（ポート変更時は読み替えます）。URL末尾のキーは不要です。以前の版で登録した`#key=...`は削除して構いません。

ソースを再読み込みしたりDockを閉じたりしても、Bun側のDiscord接続・席・カメラ判断は維持します。接続復旧時にはBunの状態を再取得します。exeを終了した場合は維持しません。

## 問題があるとき

`PORT_IN_USE`は別の起動中プロセスとポートが重なっています。勝手に他のプロセスを終了せず、先に起動したENTAKUを終了するか`--port 31338`などを指定します。ポートを変えたらOBSのURLも更新します。

`DATA_PATH_PERMISSION_DENIED`は書き込み可能な場所へ展開し直すか、`--data-dir DIRECTORY`を指定します。設定を消さずに切り分けるには`--safe-mode`を使います。このモードは保存済み設定を書き換えず、メモリ内の状態だけを使います。

`--doctor`はDiscordの認証を行わない診断です。Dockの診断JSONには名前・Discord IDを含めません。以前の版の`data/access-keys.json`は新しい版では使用せず、自動削除もしません。公開Issueへは参加者名や個人情報を含むログを貼らないでください。

```powershell
.\ENTAKU-Overlay.exe --doctor
.\ENTAKU-Overlay.exe --safe-mode --no-open --port 31338
```

終了はCtrl+Cです。アップデート前に終了し、`data/`をバックアップしてからexeを入れ替えます。

## 司会席と新しいDock

参加者の「…」メニューで「司会に指定」または「共同司会に追加」を選びます。司会は奥の丸み、一般参加者は左右の対面列、奇数の余り1人は手前の丸みに配置します。5席・司会1名なら左右2組です。司会変更はワイドで再配置し、以前の机の長さを勝手に縮めません。

下部の外観選択はシステム／ライト／ダークです。スタジオ設定、接続、診断は補助ペインにまとめています。狭いDockでは一覧の下に続きます。人物画像の編集は各参加者メニューから開きます。表示URLと操作URLは引き続きキー不要です。

## 白飛びや明るさを調整する

「露出・照明」の自動露出が既定で有効です。人物画像や名前プレートには影響しません。EV補正で明るさを調整し、必要なら「現在値で固定」を押します。強い照明を含むGLBには標準ライトを自動的に重ねません。設定と制限は[露出と照明](exposure.md)を参照してください。

## 画質と机の設定

Dockの「画質」を開きます。「標準」は自動露出を変更せず、PCF影1024・最大8灯、MSAA 4x、GTAO・SSR・FXAAを有効にします。「高画質」はGTAO・SSRと150%描画も有効にし、「軽量」は追加の画質効果を切ります。SSGIは実験オプションとして個別に有効にしてください。各項目は個別に変更できます。重い場合は反射を切るか、影の解像度や灯数を下げてください。

名札は青地・白文字が既定です。「スタジオ」内の「卓上」で白地・青文字へ切り替えられます。文字は両面に表示します。コップと卓上モニターは生成しません。

机は最初の在席配置の司会側を固定して、増席分を手前へ伸ばします。以前のデータも既存位置を基準に扱います。席予約リセットは配置と伸長基準を作り直す操作なので、カスタムスタジオとの位置関係も確認してください。

## 色・グロー・背景のぼけ

独立した「ポストエフェクト」メニューを開きます。自然な彩度1.2、コントラスト1.1が初期値です。人物は既定で除外しています。DoFの基準は人物、少し後ろ、固定距離から選べます。旧版の席や素材はそのまま使えます。詳しくは[ポストエフェクト](post-effects.md)を参照してください。

## 撮影の期限とスライダー

手動撮影は自動ONなら10秒でAUTOへ戻ります。固定したいときは自動をOFFにしてください。カメラ設定で復帰秒数、人物の画角、ワイド高さ、ニアクリップを調整できます。数値にはスライダーを併設しています。詳細は[会話に合わせたカメラ](rc9-dialogue-camera.md)を参照してください。

## 会話の左右2分割

「カメラ設定」の「応酬が続く2人を自動で左右分割」をオンにします。短い相槌では分割せず、2人が十分に話している場面を判定します。標準ではONで、共同司会と隣接席は分割しません。分割中も「この人を撮る」と自動OFFが優先します。判断の条件と制限は[RC.10の説明](rc10-dialogue-split.md)を参照してください。

## 言い淀みと終了確認

Dockは「終了確認」と「切替まで」を分けて表示します。発話グローは生のSTART/STOPに追従し、待機中の無音は発話量へ加えません。現在の待機規則は[RC.11の説明](rc11-speech-end.md)を参照してください。

## プリセット・席移動・背景読み込み

Dock上部のプルダウンの末尾から、現在のパラメータを新規JSONとして保存できます。保存先はdata/presetsです。JSON一覧から選ぶと設定をまとめて復元します。素材はdata/assetsを参照します。

参加者の「…」→「席移動」で空席へ移動、使用中の席なら入れ替えます。退出者の予約を解放すると一覧から消えます。背景は「スタジオ」の「GLB / GLTFを読み込む」から直接選択してください。別ウィンドウのシーン編集は廃止しました。詳細は[プリセットと席の操作](rc12-presets-and-seats.md)を参照してください。

## VCチャット

ライブ接続でサーバーVCへ入ると、Dockの参加者一覧下のVC-CHATに投稿を表示します。環境変数の指定は不要です。読み取り専用で、本文はファイルへ保存しません。使い方と制限は[VC-CHAT](rc14-vc-chat.md)を参照してください。

## 3DGSキャラクター

参加者の「…」→「アバターを調整」で表示方式を「3DGS」にすると、ZIPパッケージ、SPZ、3DGS PLYを取り込めます。配布物の`examples/gaussian/`に8種類の合成サンプルがあります。顔の位置と向きをプレビューで確認して「適用」してください。2D画像との混在もできます。手順は[3DGSキャラクターを使う](gaussian-avatars.md)、実機を含む確認状況は[検証記録](gaussian-validation.md)を参照してください。
