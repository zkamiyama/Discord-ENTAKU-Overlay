# 会話の左右2分割（RC.10）

## 操作

Dockの「カメラ設定」で「応酬が続く2人を自動で左右分割」をオンにします。初期値はOFFです。従来の撮影を変えずに更新でき、必要なときだけ有効にできます。「カメラの判断」の2分割欄には待機・主話者優先・応酬などの理由が出ます。マウスを重ねると割合、交代数、重なり時間を確認できます。

左右は席順で固定します。発話量の首位が変わっただけでは左右を交換しません。「この人を撮る」は即時に単独構図へ切り替わり、既定10秒で自動へ戻ります。自動OFFは時間制限なしの固定です。分割オプション自体を切ったときは通常の画面へ戻します。

## 軽量な判定

音声ではなく、既存のDiscord START/STOP区間を使います。直近10秒で次をすべて満たす2人が候補です。

| 条件 | 初期値と目的 |
|---|---|
| 各人の発話時間 | それぞれ2秒以上。ごく短い相槌を除く |
| 2人の発話占有率 | 全員の発話時間合計の85%以上。会話が2人へ集中している |
| 少ない側の割合 | 2人の合計の30%以上。一方の長話と少数の相槌を区別する |
| 会話の継続時間 | 少なくとも片方が話している実時間が5秒以上 |
| 応酬 | 有効な発話交代が3回以上、または同時発話が1.2秒以上 |
| 直近の活動 | 双方が3秒以内に話していて、3人目の継続発話がない |

同時に話した時間は各人へ計上します。例えばAが6秒、Bが4秒なら少ない側は40%です。2人が同時に話した2秒は合計では4秒ですが、重なり時間は2秒、会話の実時間も2秒として別に求めます。

交代数では700ms未満の発話を除外し、250ms以下の無音で区切られた同じ人の発話をまとめます。返答まで2秒を超えて間が空いた交代も加算しません。短い無音は発話量へ加算しません。入力区間と履歴の保持件数には上限を設け、音声モデル・文字起こし・外部APIは追加しません。

この条件が2.5秒続いて、安全な左右の構図を作れた場合にSPLITへ移ります。通常の話し始め2.5秒とは別に、分割には十分な応酬の観察時間が必要です。最初から2人が話し続けるケースでは、5秒分の会話を観察してから確認するため、分割開始はおよそ7.5秒以降です。

## 落ち着いたときの戻し方

片方が話し終わった場合は、そのSTOPから5秒待って残る話者へ絞ります。途中で再発話すると待機を取り消します。全員が無音になった場合も最後のSTOPから5秒待ちます。発話量の偏りなどで条件が崩れた場合は5秒確認してから通常構図へ戻します。

## 3人目が加わったとき

3人目をいきなり左右どちらかへ差し替えたり、画面を3分割したりしません。まず全景で会話の関係を見せ、その後で絞ります。司会者でも同じ発話規則を使い、名前やロールだけで割り込みを優先しません。

| 場面 | 動作 |
|---|---|
| 3人目の短い相槌 | 発話開始2.5秒に届かなければ、元の左右分割を維持。左右も交換しない |
| 3人目の継続参加 | 実発話2.5秒で、司会正面軸の全景へ切り替える |
| 3人以上が会話中 | 発話量の順位が変わっても、すぐ単独へ戻さず全景を維持 |
| 3人目が引く | STOPから5秒待ち、元の2人を通常の2人構図または主話者の単独へ戻す |
| 元の2人が譲り、3人目だけが話す | 元の2人の最後のSTOPから5秒待って、3人目の単独へ移る |
| 元の片方が引き、新しい2人になる | STOPから5秒後、10秒間の発話量に基づいて通常の2人構図または主話者を選ぶ |
| 待機中に再発話 | 終了待ちを取り消し、全景を維持。次のSTOPから5秒を数え直す |

4人目が後から話し始めても、既に話している3人目の2.5秒の期限は延ばしません。全景から絞る際は、話し終わった人だけでなく会話へ加わった人全体の状態を確認します。

分割終了後は最低10秒、再分割を抑えます。3人以上の全景を挟んだ場合は、全景から通常構図へ戻ってから10秒を改めて確保し、新しいペアへの即時の差し替えを防ぎます。その後も分割条件の2.5秒確認が必要です。手動撮影は即時、通信断や机の再配置は安全な全景を優先します。

## 描画

左右それぞれを8:9の望遠カメラで計算します。通常の16:9映像を切り取る方式ではありません。司会席の後方禁止、ニアクリップ、顔・名札の見通し、スタジオの障害物を両面で確認します。片方でも構図を作れない場合は、通常の撮影を続けます。

シーン・素材・WebGLコンテキストは共有し、各半面に独立した深度と後処理を持たせます。露出は1回の測光結果を共有します。人物の向きとDoFの焦点は各画面で設定し、人物の色保持設定と机の遮蔽も維持します。分割終了時は専用の描画資源を解放します。

判定が軽量でも2視点の描画負荷は増えます。重い場合は分割を切るか、SSR・SSGI・DoF・影灯数・描画解像度を下げてください。実際のフレームレートはGPU、OBS、素材によります。

## 限界と既存機能

「白熱している」という感情や議論の内容は判定しません。笑い、環境音、マイクの開きっぱなしでも条件を満たす場合があります。しきい値はこのアプリ向けの初期値で、実通話で精度を測った値ではありません。

RC.9までの発話開始2.5秒／終了5秒、10秒発話量の主役選択、正面軸の低いワイド、望遠化、ニアクリップ、司会後方禁止、手動から10秒の自動復帰、数値スライダー、画質とポストエフェクトの分離、スタジオ内の卓上、MSAA 2x、影8灯を引き継ぎます。

更新前はアプリを終了し、dataフォルダーをバックアップします。exeを入れ替え、OBSのソースとDockを再読み込みしてください。URLと素材は引き継げます。自動試験の成功は、ユーザーのGLBとOBS実GPUによる長時間運転や実通話の検証を代替しません。
