# スタジオとシーン定義

Dockの「スタジオを編集」から、GLB、GLTFと関連ファイル、またはそれらを含むZIPを取り込みます。複数のモデルがある場合は、読み込むモデルの相対パスを指定します。サブフォルダーがある素材はフォルダー選択またはZIPを使ってください。通常の複数ファイル選択では元のフォルダー構造が得られない場合があります。

## 既存のThree.js機能を使う範囲

モデル・テクスチャ・バッファ・対応する拡張の解釈はGLTFLoaderへ委ねます。LoadingManager.setURLModifierで、取り込んだファイルを認証済みBlob URLに対応付けます。Draco・KTX2・Meshoptの公式デコーダーを同梱します。標準の読込に外部CDNは不要です。任意の独自拡張まで受け入れる意味ではありません。

`models/room.gltf`から`../textures/wood.png`を参照する構成にも対応します。`../`そのものではなく、取り込み範囲の外へ出る参照を拒否します。HTTPS URLの自動取得や`file:`での任意ファイル参照は行いません。URL素材を使う場合はあらかじめプロジェクトへ保存して相対参照にしてください。GLBの埋め込み画像と既知形式のdata URIは扱えます。

## 配置

3Dプレビューで全体を確認し、モデルの位置、Y軸回転、XYZ倍率を調整します。床、箱、点光源も追加できます。単位はメートル、Y-upです。円卓と人物・カメラをまとめて移動させる基準点は`tableAnchor`で指定します。スタジオのオブジェクトはワールド座標です。

「適用」までは本番を変更しません。テクスチャ不足やロード失敗があるプレビューは適用できません。配信側で読み込みに失敗した場合も円卓と人物の描画は残し、標準ワイドを使います。プレビューの入力だけでは配信中のカメラを操作しません。

## JSON

詳細設定は「シーンJSON」で編集できます。`schemaVersion: 1`の形式を使い、未知のフィールドはエラーにします。`examples/studio-room.scene.json`は、外部素材なしで使える床と背景の例です。JSON欄へ貼り付けて「JSONをプレビューへ反映」し、確認後に適用します。

`objects`の種類は`model`、`box`、`plane`、`point-light`です。モデルの`bundleId`は取り込み結果のハッシュであり、ファイルシステムの絶対パスではありません。JSONだけを別PCへ渡しても素材は移りません。素材を含む`data/assets/studios/`も保持してください。

`tableEnvelope.maxStraightLength`は机の直線部の上限です。既定の`overflow: "hide-studio"`では、机が上限を超えたら背景を隠して参加者を維持します。`warn-only`も指定できますが、スタジオとの重なりは利用者が確認します。

## カメラの障害物

`camera.blockers`には、撮影経路や視線を遮る領域をワールド座標の`min`・`max`で指定します。Three.jsのBox3とRayを使用します。モデルの全ポリゴンから障害物を自動推定する機能ではありません。壁などの簡単な領域を指定すると、カメラを移動せずカットへ変える、別のワイドを使う、背景を隠す、という順に安全側へ切り替えます。

任意の退避構図は`camera.safeWide`の`position`・`target`・`fov`で指定します。これは円卓基準のローカル座標です。画角に人物が入らない、障害物に囲まれているなどの理由で使えない場合は、背景を隠した標準ワイドへ戻します。標準の自動カメラがどのモデルでも良い撮影経路を作れるとは保証しません。

## 上限と保存

1ファイル32MiB、ZIP64MiB、展開後128MiB、1取り込み256ファイル、保存32バンドル・512MiB、シーン64オブジェクトが上限です。描画ロード後は5000メッシュ・500万三角形の上限も確認します。この上限はフレームレートの保証ではありません。巨大な画像や極端に複雑なモデルは避けてください。

内容ハッシュで`data/assets/studios/`へ保存し、表示設定は`data/scene.json`へ原子的に保存します。シーンJSONの書き出しは配置設定の書き出しであり、素材一式のZIPエクスポートではありません。スタジオは静的背景として扱い、GLTFのアニメーション再生や内蔵カメラへの自動切替は行いません。
