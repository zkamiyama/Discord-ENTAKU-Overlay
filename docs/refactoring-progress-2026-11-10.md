## 実装した範囲

| 監査項目 | 実装と制限 |
|---|---|
| R01 設定保存と実行状態 | `SettingsService`へ処理を移した。保存後に適用が失敗すると、完了した書込を逆順に戻し、同期的な席・カメラ計画の変更も復元する。保存中のVC移動は巻き戻さない。電源断に対する複数ファイルの一括復旧は未実装 |
| R02 GPU資源 | `EffectTargets`が必要な描画ターゲットだけを保持し、解放時に参照を外す。確保・寸法変更・GPU解放にはThree.js標準のAPIを使う |
| R03 背景の保持 | `StudioVisual`は読込候補と表示中のシーンを分離する。候補の失敗・完了順の逆転では旧背景とライト数を維持し、成功時だけ入れ替える |
| R04 RPCイベント | 任意リスナーの例外ではそのリスナーだけを解除する。参加者の必須リスナーとフレーム破損は引き続き致命的エラーとして扱う。本文・認可情報・例外の自由文は診断へ出さない |
| R05 VC再同期 | `ChannelRefresh`へ定期GET_CHANNELを分離した。開いているIPCでのタイムアウトだけ750ms後に再試行し、3回連続失敗で切断する。初回同期、認証・権限エラー、不整合な応答は対象外 |
| R06 addonとの境界 | SSR・DoFのシェーダー補正とBloomの内部参照を`addon-adapters.ts`へまとめた。補正する文字列がない場合や複数ある場合は明示的なエラーにする。Three.jsの更新はしていない |
| R07 WebSocket | 接続中のソケットを所有者として判定し、古いソケットの遅延イベントを無視する。切断時のタイマー解放、再接続の重複防止、チャットの再購読を試験した |
| R08 描画の復旧 | 描画効果が例外で失敗した場合、500ms後と、その再失敗から2秒後に再試行する。連続3回失敗後は設定・シーン・画面寸法などが変わるまで直描画へ退避する。品質を自動で下げる機能は未実装 |

背景の読込に失敗した場合は、旧背景を表示したまま診断に`STUDIO_LOAD_FAILED`を出す。読み込み中も既存の背景を表示できるため、その理由だけで画面側を代替カメラへ切り替えない。サーバーの安全なワイドへの退避や、指定障害物の検査は維持している。

R02について、監査の解釈を補足する。Three.jsでは`dispose()`後も、再び使うことでGPU資源が再生成される場合がある。旧実装を無条件に「解放後アクセスのバグ」とは扱わない。今回の目的は、アプリ側の所有権と再生成のタイミングを明確にすることである。

## 一部だけ進めた項目

R09はHTTPハンドラーから設定保存を分離したが、ルーター全体の分割はしていない。R14はスナップショット作成とJSON化を1回の配信で共用した。配信間隔、メッセージ形式、チャットと映像の分離は変更していない。差分配信や実負荷の計測は別に残る。

R24はスタジオ、アバター、プリセット選択状態のJSON置換を共通化した。1ファイルごとの一時書込・renameと、必要なバックアップを扱う。プリセットの新規作成は従来の上書きしない方法を維持し、席予約のSessionStoreは変更していない。

## 変えていないこと

発話開始1.5秒、終了確認2.5秒＋猶予5秒、主話者の集計、隣接席の構図、手動撮影からの自動復帰は変更していない。画像・シーン・プリセットの保存形式、URL、ローカルキーを付けない方針、Discordの要求スコープも同じである。

Three.js 0.187.0とBun 1.4.4を維持した。GLTFLoader、標準レンダーターゲット、SSRPass、GTAOPass、BokehShader、UnrealBloomPassを使い続けている。独自のglTFローダーやGPU資源管理機構へ置き換えていない。

## 残っている作業

AppEngineと撮影状態機械の本格的な分割、構図・発話集計・影のキャッシュ、Dockの共通フォームとポーリング削減、HTML/CSS整理、画像編集の分割、資産インデックス、型付きコマンド、未使用コードの除去、CIの分割、実GPU計測などは未実装である。監査の各候補を完了扱いにせず、次の変更単位として残す。

複数ファイルの保存中にOSやプロセスが突然終了した場合の一括復旧も保証しない。今回の巻戻しは実行中に捕捉できた例外に対するものなので、更新前の`data/`バックアップは引き続き必要である。

## Bunでの更新

起動中のアプリを終了してから、次を実行する。

```powershell
git pull --ff-only
bun install --frozen-lockfile
bun run build:web
bun run start --live --compat-auth --accept-streamkit-compat
```

OBSのDockとブラウザソースを再読み込みする。保存済みのパラメータや素材を初期化する必要はない。バージョン表示はRC.15のままなので、更新確認にはコミットも使う。
