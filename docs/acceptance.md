# 実機受け入れ試験

この文書は未完了の試験手順であり、成功記録ではない。実施時はOS、Discord、OBS、アプリのコミットと結果を記録する。URLのアクセスキー、OAuthコード、アクセストークン、実参加者名を診断資料へ含めない。

## P0: IPCと認証

利用者が非公式なStreamKit互換認証の説明を確認し、明示的なフラグ付きで起動する。Discordの認可画面を許可した場合と拒否した場合を確認する。拒否や期限切れで認可画面を無限に開かないことを確かめる。

通常のサーバーVCに2人以上で入り、本人と他者それぞれのSTART/STOP、ミュート、入退室、名前、アイコンを確認する。参加中のVCを変更し、古いチャンネルの遅延イベントが新しい参加者状態へ混ざらないことを確認する。Discordを終了・再起動し、unknownからスナップショットと購読を再構成できるかを調べる。

## OBS

ブラウザソース1920×1080とカスタムブラウザDockを設定する。映像の透過、日本語プレート、裏面減光、発話リングを確認する。ソース再読み込み、シーン切替、非表示時のソース終了、Dock閉鎖と再表示を行い、Bunの席予約や発話接続がページの寿命に依存しないことを確認する。

## 席とカメラ

A/B/Cの参加からBだけを退出させ、Dを入れた後でBを戻す。Bの論理seatIdが維持されることを確認する。予約数が最大同時人数を超える場合に、席予約を優先して容量を増やすことを確認する。増席時だけ机を伸ばし、退出では縮めない。32席を予約した後の新規参加者は待機にする。

短い相槌、1秒以上の発話、250ms以内の間、3人以上の同時発話、交互発話、長い独話を試す。カメラの切替理由をDockで確認する。HOLDでも取得経路の切断や対象者の消失時には安全なワイドへ戻す。撮影中の素材やプレートが画面端で欠けないかも見る。

## 配布と長時間運転

Bun/Node.jsのないWindows環境で開発用ZIPを展開し、デモを起動する。日本語を含む保存先、読み取り専用の保存先、使用中ポート、破損したセッションファイルを試す。既存ファイルを黙って上書きして復旧したように見せないことを確認する。

16人で1080p/60fpsを目標に、CPU、GPU、メモリ、フレーム時間を測る。数値は測定前に保証しない。2時間以上動かし、接続断、参加者の入れ替わり、同一ソースの再作成によるメモリ増加を確認する。
