# VCチャットからノートを紹介する

参加中のDiscord VCチャットにMisskeyのノートURLを貼ると、映像の下から紹介カードが現れます。次の対象URLでカードを差し替え、Dockの「ノート紹介」→「紹介を取り下げる」で終了します。ハッシュタグ付きの3Dカードとは別の機能で、紹介するノートにハッシュタグは不要です。

## 操作

1. ENTAKUをDiscordへ接続し、DockのVC-CHATが「受信中」になったことを確認します。
2. 設定で許可したインスタンスの`https://インスタンス/notes/ノートID`を、参加中のVCチャットへ投稿します。初期設定は`https://otomad.site`です。
3. 取得できた公開ノートを映像に表示します。新しいURLが届くと、現在のカードが下へ退場してから次のカードが入場します。
4. 紹介を終えるときはDockの「紹介を取り下げる」を押します。取得待ちの要求も取り消します。

時間による自動終了はありません。取得中・取得失敗の間は現在のカードを保持します。取り下げたノートを再度紹介するときは、新しいチャット投稿としてURLを貼ってください。

紹介元のチャット投稿が削除された場合や、編集で対象URLがなくなった場合は取り下げます。VC移動・Discord切断でも表示を終了します。Discord側で編集・削除イベントを取得できない場合は追従できないため、Dockの取り下げを使います。起動時のチャット履歴やDockの再読み込みを、新しい紹介のきっかけにはしません。

## カードの大きさ

| 項目 | 動作 |
|---|---|
| 幅 | 映像ページの横幅の80% |
| 高さ | 内容に必要な高さ。上限は映像ページの高さの50% |
| 長い本文 | 実際の折り返しを測り、全文が収まるよう文字サイズを縮小 |
| 改行や投稿者名が極端に長い場合 | カード全体も縮小して上限内に収める |
| カメラ移動・SPLIT | 画面全体に1枚表示し、カメラの角度や分割数で大きさを変えない |

本文の行数上限や末尾の省略は設けません。文字量に対して画面が小さすぎる場合は、全文表示を優先して文字が小さくなります。本文・投稿者・取得元インスタンス・VCの紹介者・添付件数を表示します。添付画像・動画の再生、外部画像の取得、動くMFM、カスタム絵文字画像の取得は行いません。MFMは静的な文字に変換します。

## 設定ファイル

初期設定と編集用のテンプレートは[`config/note-introduction.json`](../config/note-introduction.json)です。インスタンス名を取得処理へ埋め込まず、このJSONで指定します。

```json
{
  "schemaVersion": 1,
  "enabled": true,
  "instances": ["https://otomad.site"],
  "includeHome": false
}
```

Dockの「ノート紹介」→「設定ファイル」→「JSONを書き出す」で現在の設定を保存できます。`instances`を編集し、「JSONを読み込む」で適用してください。設定JSONは32 KiBまでです。

| キー | 指定する値 |
|---|---|
| `schemaVersion` | `1` |
| `enabled` | `true`で自動紹介を有効、`false`で無効 |
| `instances` | HTTPSのインスタンスorigin。最大8件。パスやポート番号は含めない |
| `includeHome` | `false`はパブリックのみ。`true`はホーム公開も対象 |

ホスト名は完全一致で検査します。似たドメインや、許可先のサブドメインを自動で追加しません。認証情報、ローカル宛先の表記、未知の設定キーは受け付けません。DNSによる接続先の固定は行わないため、運用者が管理・確認したインスタンスを指定します。

起動時にファイルを指定することもできます。

```text
ENTAKU-Overlay.exe --note-introduction-config config/note-introduction.json
```

この例は既定のデモ起動です。ライブ起動時は通常のライブ接続引数と組み合わせます。指定ファイルの検査に失敗した場合は起動を停止します。

読み込んだ設定はSQLiteに保存し、次回以降も使用します。JSONファイルを後から編集しただけでは実行中の設定は変わりません。Dockで読み込むか、起動引数で明示的に指定してください。環境パッケージにも設定を含めますが、現在のカード本文やVCチャット本文は含めません。紹介設定を持たない以前の環境パッケージでは、受け取り側の紹介設定を保持します。

## 取得範囲と制限

取得には匿名の`POST /api/notes/show`を使います。サーバーや投稿者がログインを要求する場合、非公開・非表示のノート、CWやセンシティブ指定のあるノートは表示しません。取得先の認識するリモート投稿も対象になり得ます。

| 取得時の上限 | 値 |
|---|---:|
| 取得完了までの時間 | 10秒 |
| 応答データ | 1 MiB |
| 本文・アンケート選択肢の各入力 | 16,000 UTF-16コード単位 |
| 投稿者名・引用・選択肢を含む総入力 | 32,768 UTF-16コード単位 |

文字列の上限は見た目の文字数とは異なり、変換後の本文にも32,768 UTF-16コード単位の上限があります。上限を超えたノートは省略して表示せず、取得失敗として現在のカードを保持します。

Misskeyの公開範囲とCWは[公式のノート説明](https://misskey-hub.net/ja/docs/for-users/features/note/)に従います。調査した対象forkの[`notes/show`](https://github.com/OtomadSite/system/blob/13cde5a03c560e0bfbe9ec475157f29ae4ba1653/packages/backend/src/server/api/endpoints/notes/show.ts)は認証必須ではありませんが、投稿者とサーバーの閲覧制限を検査します。この固定ソースが現在の配備内容と同一であることは再確認できていません。

連投では未処理の対象を最新1件へまとめ、要求の開始間隔を少なくとも1秒空けます。HTTP 429では`Retry-After`を尊重します。確認したソースの`notes/show`に固有の毎分件数は定義されておらず、運営側の確定した許容量も確認できませんでした。CDN等の制限もあるため、無制限とは扱いません。[API共通の制限処理](https://github.com/OtomadSite/system/blob/13cde5a03c560e0bfbe9ec475157f29ae4ba1653/packages/backend/src/server/api/ApiCallService.ts)も参照してください。

カードは取得した時点の内容です。Discordの紹介元投稿の変更には追従しますが、取得後のMisskeyノート自体の編集・削除を監視する接続は追加していません。

## 検証

単体・結合試験はURL検査、全文変換、遅延応答の破棄、取得制限、取り下げ、設定保存の失敗、再起動、環境パッケージとの往復を対象とします。ブラウザ試験は実際のカード寸法、全文の保持、差し替え、取り下げ、リサイズ、SPLITとの併用に加え、設定JSONの読み込み・書き出し、許可先の変更、再読み込み後の保持、不正なJSONの拒否を確認します。合成チャットとAPI応答を使用し、実Discordアカウントや投稿の作成は行いません。

実Discord、対象インスタンスへの今回の実API接続、WindowsのOBS/CEFでの確認は未実施です。

設計判断は[ADR 0033](adr/0033-vc-note-introduction.md)に記録しています。
