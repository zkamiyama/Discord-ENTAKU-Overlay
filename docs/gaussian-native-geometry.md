# 3DGS単体の反射と影

proxy.glbを用意せずに、SPZ/3DGS PLYから深度・法線を描き、SSRとキャストシャドウへ接続しました。既存のproxy付き素材は、引き続きproxyを優先します。実装理由と一次資料は[ADR 0024](adr/0024-native-gaussian-geometry.md)を参照してください。

## 操作

1. Dockの「アバターを調整」で3DGSを選び、GLBを添付せずSPZまたは3DGS PLYを取り込みます。ZIPではmanifestのproxyを省略してください。
2. 配布サンプルの `examples/gaussian/character-01-native.entaku.zip` でも試せます。ソース版は `bun run fixtures:gaussian` で `.generated/gaussian-fixtures/` に生成します。
3. 「画質」の「影」と「画面内の反射（SSR）」を有効にします。影を受ける机・床と、DirectionalLightまたはSpotLightが必要です。
4. 影が欠ける場合は「3DGSの影・反射形状の不透明度閾値」を0.3から下げて比較してください。薄い不要なGaussianが影に出る場合は上げます。値は設定・プリセットへ保存されます。

閾値の範囲は0.01〜0.99です。旧設定には0.3を補います。色・発話グローのアルファとは独立した値です。

## 実装範囲

| 項目 | 動作 |
|---|---|
| SSR | 3DGSの外観に加え、本体由来の深度・法線を公式SSRへ渡す |
| 落影 | ライト視点からGaussianを描き、既存PCFシャドウマップを使う |
| DoF | 人物を効果に含める場合、カラー描画後に本体由来の深度を使う |
| 重なり | 閾値を超えるGaussianの最前面をZテストで選び、前後の人物の深度を平均しない |
| 分割 | 視点ごとの深度・法線を描き、カラーのLoDやソートを共有して誤用しない |
| 更新 | 変換・表示・素材・ライト・設定が変わると影を更新。カメラや発話色だけでは更新しない |
| 資源 | 元のPackedSplatsテクスチャを借りる。追加のソートworkerや人物別render targetはない |

法線は最短軸による近似です。深度は投影したGaussian中心の深度で、楕円体への正確なレイ交点や、透明な層を積算した深度ではありません。小さなquadをインスタンス描画しますが、人物のポリゴンメッシュへ変換しているわけではありません。

## 自動検証

型検査と単体・結合テストは300件合格、失敗0件でした。ブラウザは69件の全体実行が合格し、その後に追加したnative資源試験を含む2件も合格しました。重複を除く最終70ケースを確認しています。300件は77ファイル、149,308 assertionsです。

さらに、native深度・法線、SSR・落影、分割・後処理の3ケースをRTX 4080でも実行し、全件合格しました。Linux単体実行ファイルのビルドと、PATHを空にした隔離HTTPスモークも合格しています。Windowsネイティブ実行やOBSの確認とは区別します。

機能試験はChromium 158.0.8127.18 / SwiftShaderで実行しました。ソフトウェア描画の時間を実GPU性能には使用していません。

| 試験 | 確認内容 |
|---|---|
| 深度・法線の画素読戻し | 深度3.0mと2.5m、描画順に依存しない最前面、既知の回転法線、非一様変換の逆転置、球・針状の代替法線 |
| proxyなしSSR | 赤と青の外観変更で反射成分が変化。7,102画素で差を検出 |
| 直接落影 | DirectionalLightとSpotLight。ライト移動で影の位置が変わり、退出後に影が残らない |
| 自己遮蔽・設定復帰 | 幾何パス追加前後の主画面差0。効果OFFへ戻した差0 |
| 閾値 | 低アルファを閾値で除外・復元。0.99で除いた素材の影が残らない |
| 分割・LoD・後処理 | 逆向き2視点、連続CUT、解像度、SSR・影・AO・DoF・Bloom・MSAA・FXAAの組み合わせ |
| 実アプリ | proxyなしの異なる8素材を取り込み、個人ごとの色、席、2D混在、実行時のnativeパスを確認 |
| 寿命 | 共有quadの最終解放、元テクスチャの所有者保持、表示終了と例外時の状態復元。実ブラウザでも素材交換・エディタ・分割を3回反復し、native全解除後のインスタンス0と資源数の上限を確認 |

数値は合成fixtureの結果です。DirectionalLightの影は1,126画素、SpotLightの影は2,792画素を基準画像より暗くしました。ライト移動後も影を検出し、人物なしの場合の影の残留は0でした。法線・深度は名前や定数の一致だけでなく、GPUの出力値を独立した期待値と比べています。

## 実GPUの短時間測定

2026年11月10日に、接続PCのRTX 4080、ドライバー610.88、Core i9-13900Kで実行しました。OSはWSL2 Linux 6.18.33.1、Chromium 158.0.8127.18です。WebGLのrenderer文字列は `ANGLE (Microsoft Corporation, D3D12 (NVIDIA GeForce RTX 4080), OpenGL ES 3.1)` でした。WindowsネイティブブラウザやOBSでの測定ではありません。

1920×1080、DPR 1、カラーのLoD予算500,000、SSR処理解像度0.5、影1024px、AO・GI・DoF・通常Bloom・MSAA・FXAAはOFFです。Fresnel発話グローは1人に付けています。人物は各35,913 Splatの合成素材で、8体は色と形状を変えた8つの別ソース、合計287,304 Splatです。各ソースのPackedSplats配列は1,048,576 bytesで、これは容量確保を含むCPU配列量です。ファイルの圧縮サイズやGPU使用量とは異なります。

各条件を40フレーム準備してから60フレーム測定しました。GPU時間は `EXT_disjoint_timer_query_webgl2` の結果で、disjointは検出されませんでした。フレーム間隔とCPUの描画命令投入時間も別に記録しています。

| 条件 | GPU p50 / p95 (ms) | フレーム間隔 p50 / p95 (ms) |
|---|---:|---:|
| 1体・通常・影1灯＋SSR | 2.405 / 6.178 | 16.70 / 16.90 |
| 1体・分割・影1灯＋SSR | 2.280 / 3.580 | 16.70 / 16.80 |
| 8体・通常・影1灯＋SSR | 1.953 / 3.121 | 16.70 / 16.80 |
| 8体・分割・影1灯＋SSR | 3.965 / 8.150 | 16.70 / 17.40 |
| 8体・通常・移動中・影8灯＋SSR | 3.741 / 4.737 | 16.70 / 18.20 |

通常1/8体、単画面/分割、影OFF/ON、SSR OFF/ONの16条件に、nativeパスなしの比較2条件、8灯で人物を移動する条件を加えた19条件です。全条件の集計値、renderer文字列、各視点の位置・描画数、資源数は[測定JSON](measurements/gaussian-native-rtx4080.json)にあります。

静止条件では準備後60フレーム中の影再描画は0回でした。移動条件では8体×8灯×60フレームで3,840回の影用drawを記録しています。このキャッシュの有無が負荷に影響します。分割では各人物の画面上の大きさも変わるので、通常画面との単純な速度比では評価できません。

これは本番と同じ描画クラスを使った短い試作シーンの測定です。全Dock・Discord処理を含む配信の長時間保証ではなく、学習済み実キャラクターや数百万Splatの素材へも外挿できません。初回の分割ベンチマークはカメラの姿勢設定が足りなかったため除外し、姿勢の検査を追加した再実行だけを上表に使用しました。

```sh
# Bun、Playwright Chromiumを導入したリポジトリのルート
bun run bench:gaussian-native
# ソフトウェア描画での動作確認だけを行う場合
bun run bench:gaussian-native --software
```

WSL2の今回の測定では、`GALLIUM_DRIVER=d3d12 MESA_D3D12_DEFAULT_ADAPTER_NAME=NVIDIA` を指定しました。`ENTAKU_CHROMIUM_PATH` で実行ファイルを指定できます。実GPU用コマンドはSwiftShader/llvmpipeを検出すると終了し、ソフトウェア描画を実GPUとして報告しません。結果と各条件のPNGは `.work/native-benchmark/` に保存します。

## 残る確認と制約

| 項目 | 現在の状態と再現方法 |
|---|---|
| 学習済み人物・髪・衣服 | 素材未提供。使用予定のSPZ/PLYをproxyなしで取り込み、閾値0.1/0.3/0.6、単体/8体、近距離/遠距離で形状とちらつきを比較する |
| Windows/OBS | 未実施。同じ配布exeをデモ起動し、新規OBSブラウザソース1920×1080で影・SSR・分割を比較する |
| 長時間運用 | 未実施。実素材で素材交換・入退室・席移動・分割切替を継続し、診断値とフレーム時間を記録する |
| GPUメモリbytes | ブラウザから信頼できる実配分量を取得していないためnull。CPU配列量・texture数とは区別する |
| 半透明・浮遊Gaussian | 閾値は各Splatへ適用する。薄い層が多数重なって見える表面を取りこぼす場合があり、閾値変更だけで完全には解決しない |
| 低いカラーLoD | 幾何パスは元データのままなので、カラーの粗いシルエットとずれる場合がある |
| 本体の受影と再照明 | 今回の追加外。人物が環境へ落とす影と、人物の外観が机へ映るSSRに対応 |

幾何用パスはカラー用LoD数ではなく元Splat数に比例します。軽量化は影灯数・影解像度・SSR解像度の調整で行い、非常に大きい素材では軽いproxyの指定も利用できます。
