# リファクタリング第2段階（2026-11-10）

[第1段階](refactoring-progress-2026-11-10.md)の続きとして、[監査](refactoring-audit-2026-11-10.md)で残ったサーバー、ドメイン、Dock、描画、保存、テストを整理した。本番映像の既定値や撮影のタイミングは変更していない。最新の仕上げと確認範囲は[実装・検証記録](refactoring-completion-2026-11-10.md)を参照。

## 変更した構造

| 対象 | 今回の変更 |
|---|---|
| サーバー | app.tsからstatus・assets・commandsのルートを分離。Command判別共用体と入力検査をサーバー／Dockで共用 |
| 参加者・席 | MembershipStateへ在席・発話状態を移し、updateSeatLayoutへ机の拡張規則を分離 |
| カメラ | CameraContextに席と画像寸法、2人構図の可否をキャッシュ。不要なcapacity引数と未使用関数を除去 |
| 発話集計 | 同じ時刻の集計結果・区間を共用。入力イベント、時刻、集計期間の変更で無効化 |
| 撮影状態の表示 | 診断reasonとは別にphaseを公開。Dockの終了確認表示は英語の文字列末尾に依存しない |
| Dock設定 | 共通SettingFormへ保存・排他・エラー・disabled状態の復元を移し、同じ値の重複保存を省く |
| Dock更新 | スライダーの常時同期を除去。露出と診断の取得を共用し、非表示中のポーリングを停止 |
| UI資源 | HTMLを9部品、CSSを4部品に分割しビルド時に展開。展開結果は従来の出力とバイト単位で一致 |
| アバター | 描画AvatarをOverlayから分離。画像読込と矩形選択の計算を編集画面から分離 |
| スタジオ | ZIP展開・検査をarchive.tsへ分離。通常のGLTF検証では追加WebGLコンテキストを作らない |
| 影・反射 | SceneEffectsIndexへライト・影境界・SSR対象を集約。カメラだけの移動では再選別しない |
| 描画状態 | 複数パスで変更するレンダーターゲット・色空間・レイヤー・クリア状態の復元を共通化 |
| 保存 | 席予約も共通atomic JSON書込へ移行。プリセット一覧は変更のないJSONを再解析しない |
| 開発・CI | 未使用コード検査を常時有効化。ブラウザ試験を2シャードへ分け、UI／描画の選択コマンドと計測コマンドを追加 |

プリセット一覧のキャッシュはファイルのinode・サイズ・mtime・ctimeを照合する。一覧をキャッシュしても、適用時の内容と素材の検証は省略しない。削除・破損・外部編集を試験した。

## 保持した動作

発話開始1.5秒、終了確認2.5秒、その後の5秒猶予、主話者判定、隣接席の単一カメラ、手動撮影からの自動復帰を維持する。既存data、画像・GLB・プリセット形式、Discordの認可スコープ、キー不要のローカルURLは変えていない。

キャッシュは、席移動・入退室・カスタム画像・構図パラメータ・机の伸長・スタジオ切替で更新する。測光の更新キーは影の更新キーと分離した。影のキャッシュを更新しても、自動露出の初期測光を毎フレームやり直さない。

## 計測で確認したこと

制御処理は6・16・32人の合成データで、旧版と新版を交互に3回実行した。各回は200tickをウォームアップし、1000tickを計測した。下表は各回の中央値をさらに3回分の中央値にした値であり、実通話やGPU描画のフレーム時間ではない。

| 人数 | tick中央値：旧版 | 新版 | tick p95：旧版 | 新版 |
|---|---:|---:|---:|---:|
| 6 | 0.0163ms | 0.0123ms | 0.0710ms | 0.0392ms |
| 16 | 0.0268ms | 0.0190ms | 0.0792ms | 0.0488ms |
| 32 | 0.0458ms | 0.0303ms | 0.1053ms | 0.0614ms |

数値は当該実行環境の参考値であり、同じ改善率を別のPCへ保証しない。生データと比較対象コミットは[domain-stage2.json](benchmarks/domain-stage2.json)に記録した。新しいドメインコードはコミットfc992deと一致する作業ツリーで計測した。

描画計測コマンドは6・16・32席、単独／左右分割、標準／高画質の12条件を用意した。480×270・各5サンプルのSwiftShader実行で動作を確認した。これは計測プログラムのスモーク試験であり、実GPUの速度を示す結果ではない。

この試験ではライトのshadow mapがシーン破棄後にも残ることを検出した。標準Light.disposeをシーン解放に加えた。現行版の再試験では、全12条件の破棄後にジオメトリ0、テクスチャ1で一定だった。残る1枚はThree.js内部の16×16のDFG_LUTであり、アプリの影用テクスチャとは区別する。renderer.info.memoryの値はジオメトリ・テクスチャの数で、GPU使用量のバイト数ではない。

## 自動試験

型検査にはnoUnusedLocalsとnoUnusedParametersを追加し、単体・結合242件が成功した。単体・結合試験では、キャッシュ無効化、プリセットの外部変更、HTML/CSS展開、画像座標、コマンド検査、影の更新、ライト資源解放を確認する。

既存のブラウザ49件に、入力のdisabled状態とスライダー同期、通常GLTFのWebGL不要検証を追加した。チェック状態が戻る失敗を検出し、同じ値の再保存を抑えて修正した。反射ON時の対象リスト更新漏れも修正してから、全51件の回帰を再実行した。

GitHub CIは2シャードで全件を実行する。ローカルで分割一覧を照合した結果、26件と25件に分かれ、全51件を網羅する。実行結果は対象コミットのCIで確認する。

## 監査候補の扱い

R09・R10・R12・R13・R15・R18〜R20・R22〜R25・R27・R29・R31は、上記の抽出・共通化・回帰で対応した。R11は公開状態に加えて候補と絶対期限を分離した。R16・R17・R21はAvatar・フレーム補間・ProgramRenderer・パス復元・画像処理・AvatarPreviewへ分離した。汎用フレームワークへの置換は採用しない。

R14は第1段階の配信時JSON共用を維持し、差分配信は採用しなかった。R26はプリセット一覧をキャッシュし、最大256画像の容量検査は外部変更を含む正確さを優先して残した。R28は参加者・発話の索引と値が変わらないDOM更新の抑制を入れ、完全な仮想DOMは導入していない。

R30は繰り返し可能な計測手段を追加した。実スタジオ・実GPU・OBS本体の1080p60と長時間運転は未確認である。R32は[公開前チェックリスト](release-checklist.md)と手動のRelease下書きワークフローを用意したが、認可方式の配布条件を確認済みとは扱わず、公開処理は実行していない。

## 開発用コマンド

```powershell
bun run check
bun run test:e2e
bun run test:ui
bun run test:render
bun run bench:domain
bun run bench:render --headed --width 1920 --frames 120
```

ソフトウェア描画で計測プログラムだけを確認する場合は、次を使う。

```powershell
bun run bench:render --software --width 480 --frames 5
```

描画結果は.work/render-benchmark.jsonへ保存する。実GPUを使う指定でも環境によってソフトウェア描画へ退避する場合があるため、deviceとsoftwareを必ず確認する。

## 更新

アプリを終了しdataをバックアップしてから、git pull --ff-only、bun install --frozen-lockfile、bun run build:webを実行し、再起動する。OBSのDockとブラウザソースも再読み込みする。バージョン表示はRC.15のままで、設定や素材の初期化は不要である。
