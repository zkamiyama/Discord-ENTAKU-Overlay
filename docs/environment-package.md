# 環境を1つのZIPで渡す

Dockの「環境パッケージ」から、現在の設定と必要な素材を`entaku-environment.entaku.zip`へ書き出せます。受け取り側も「環境パッケージ」でZIPを選び、内容を確認して適用します。外部モデルや付属テクスチャを個別にコピーする必要はありません。

この機能を含むENTAKU同士で利用してください。保存形式は`schemaVersion: 1`です。対応していない形式や設定は適用前にエラーになります。異なるGPUやOBSの画素数まで同じにする機能ではありません。

## 渡す側の手順

1. ステージ、人物への素材の割り当て、席、描画設定を調整します。
2. Dock最上段の「環境パッケージ」を開きます。
3. 「現在の環境を書き出す」を押します。
4. ダウンロードされた`entaku-environment.entaku.zip`を渡します。

書き出すのは、その時点の設定と参照されている素材です。名前付きプリセットを先に保存する必要はありません。Discordに接続している場合、現在の参加者名とアイコンも再現プレビュー用に収集します。必要なアイコンを取得できなかった場合は書き出しを失敗として知らせます。

## 受け取る側の手順

1. Dockの「環境パッケージ」を開き、受け取ったZIPを選びます。
2. 作成日時、ENTAKUのバージョン、素材と人物の件数、サイズを確認します。この段階では現在の設定を変更しません。
3. 「この環境を適用」を押します。現在の設定と人物への素材の割り当てを置き換えます。
4. 「保存時の出演者でプレビュー」を開くと、Discordに接続せずに出演者と配置を確認できます。

通常の映像ページは現在接続しているDiscordの参加者を表示し続けます。保存時の出演者を通話へ追加する処理はありません。プレビューは別の映像ページで、発話とミュートを中立状態にします。VC-CHATとMisskeyのライブ投稿は表示しません。

適用した設定は再起動後も残ります。プレビューには保存時の出演者と適用済みの設定を使い、あとからDockで変更した設定も反映します。

## 何が入るか

| 対象 | 保存する内容 |
|---|---|
| ステージ | スタジオ、机、配置、外部GLB／GLTFと付属テクスチャ・バッファ、モデルと発話者の対応 |
| 描画 | 画質、描画解像度の倍率、影、露出・照明、ポストエフェクト、3DGSの描画予算、番組表示 |
| カメラと席 | FOVなどのカメラ設定、左右分割の設定、AUTO／HOLD、司会席、座席の配置と割り当て |
| カスタムアバター | 前後の画像、切り抜き・顔位置・表示範囲、大きさ・位置・向き、DiscordユーザーIDとの対応 |
| 3DGS | 元の素材一式と人物ごとの調整値。元の素材IDを維持 |
| 出演者 | 保存時の名前、DiscordユーザーID、表示対象の一覧、プレビュー用の標準アイコン |
| Misskey | インスタンス、ハッシュタグ、公開範囲、表示件数・文字数・寿命、禁止語と除外ユーザーなどの設定 |
| Dock | テーマの選択 |

同じ素材を複数の人物やモデルが参照していても、同じ内容のファイルは1つにまとめます。GLTF内の相対パスも保持します。

未使用の素材、名前付きプリセットの全履歴、過去の全チャンネルの席、認証情報、受信済みチャットやMisskey本文、発話状態、カメラアニメーションの途中位置は含めません。ポート、データ保存先、OBSのソース設定など、起動環境の設定も移行対象外です。データ全体をバックアップするときは、アプリを終了して`data/`を保存してください。

## Discordの画像は最新情報を優先する

通常のDiscord接続ではDiscordから受け取った現在のアバターURLを使います。URLが変われば新しい画像を取得し、アバターが削除された場合も保存画像へ戻しません。

ZIPに入る標準アイコンは保存時の出演者を再現するための画像です。通常のDiscord画像取得とは別の経路で読み込みます。保存画像の内容をDiscordの画像と定期的に照合する処理はありません。ZIPのSHA-256検査はパッケージや素材の破損と取り違えを検出するために使います。

カスタム画像や3Dモデルを人物に割り当てた設定は、そのまま移行します。その人物が通常のDiscord接続へ現れたときも、割り当てた素材を使います。

## サイズと失敗時の扱い

| 上限 | 値 |
|---|---:|
| ZIP全体 | 512 MiB |
| 展開後の合計 | 512 MiB |
| パッケージ内の1ファイル | 128 MiB |
| 設定manifest | 4 MiB |
| ZIPのエントリー数 | 4,096 |
| 保存する人物情報 | 256人 |
| 保存時プレビューの表示対象 | 32人 |

個々の素材には画像・スタジオ・3DGSで従来から設けている制限も適用します。受け取り側の素材保存先に空きが足りない場合は適用できません。書き出しは無圧縮ZIPなので、画像やSPZを再圧縮する時間を抑えられますが、512 MiBぎりぎりの素材はZIPの管理情報が加わると上限を超えることがあります。

内容確認では一時保存先に素材を復元し、ファイルの内容、モデルの依存関係、元の素材IDを検査します。適用時には素材を先に保存し、最後に設定と現在の座席をまとめて確定します。確認後に設定や接続先が変わった場合は、そのまま上書きせず内容確認をやり直します。

検査・保存に失敗した場合、現在の設定は維持します。途中まで保存した未参照の素材が残ることはありますが、既存の素材を削除して戻す処理は行いません。

## 検証と実装

自動試験では新しい保存先への復元、GLTFの相対依存、前後の画像、3DGSの調整値、設定の再起動後の保持、設定変更との競合、SQLiteの保存失敗を確認します。ブラウザ試験では実際のZIPダウンロードと再適用、テーマ・カメラ・Misskey設定、ライブ参加者と保存プレビューの分離を確認します。

Discordの実機接続とWindowsのOBSでの見え方は別途確認が必要です。最新コミットの実行結果は[CI](https://github.com/zkamiyama/Discord-ENTAKU-Overlay/actions?query=branch%3Afeat%2Fportable-scene-packages)を参照してください。

設計の理由、API、保存形式は[ADR 0032](adr/0032-portable-environment-packages.md)に記載しています。
