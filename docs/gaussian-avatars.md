# 3DGSキャラクターを使う

静的な3D Gaussian Splatting（3DGS）素材を参加者に割り当て、円卓の席へ表示できます。従来のPNG・静止WebPと混在できます。素材の取り込み、顔位置と向きの調整、保存、別の参加者への割り当てはDockから行います。

この機能の実装と検証範囲は[検証記録](gaussian-validation.md)、素材を作る人向けの仕様は[キャラクターパッケージ](gaussian-package.md)に分けています。実GPUとOBS本体での確認結果は、ブラウザの自動テストと区別して記録します。

## サンプルを表示する

1. 配布ZIPを展開し、`Start-Demo.cmd`を起動します。ソースから動かす場合は`bun install --frozen-lockfile`、`bun run fixtures:gaussian`、`bun run dev`を順に実行します。
2. Dockの参加者の「…」から「アバターを調整」を開きます。
3. 「表示方式」を「3DGS」に変更します。
4. 「ZIP / SPZ / 3DGS PLY」に`examples/gaussian/character-01.entaku.zip`を指定し、「取り込む」を押します。ソースから生成したサンプルは`.generated/gaussian-fixtures/`にあります。
5. 状態が「利用可能です」になるまで待ち、プレビューをドラッグして見た目を確認します。
6. 「適用」を押します。映像ページの該当参加者に反映されます。

配布物には、形状・色・Splat数の異なる8種類の合成素材が入ります。動作の切り分け用で、実写人物の画質や重さを代表する素材ではありません。生成物はCC0-1.0、生成コードはリポジトリのMITライセンスです。

取り込みは素材を保存する操作です。「適用」は参加者との対応を保存する操作です。エディタで調整中の映像は適用するまで本番へ反映しません。「キャンセル」しても、取り込んだ素材は保存済みの一覧に残ります。

## 自分の素材を取り込む

背景を除いた静的な人物素材を用意します。次の形式を受け付けます。

| 素材 | 取り込み方 |
|---|---|
| ENTAKUキャラクターパッケージ | `manifest.json`とSPZまたは3DGS PLYを含むZIPを選ぶ |
| SPZ | 単体ファイルを選ぶ。標準形式のv1〜v4に対応 |
| 3DGS PLY | 単体ファイルを選ぶ。ASCIIまたはbinary little-endian形式に対応 |
| 代理メッシュ | 単体素材と同時に任意のGLBを選ぶ。ZIPではmanifestから参照する |

一般的な点群PLYには、Gaussianの大きさ・回転・不透明度がないため対応しません。SPZの独自拡張や事前生成LoDを含む一部の形式も受け付けません。対応するプロパティと制限は[パッケージ仕様](gaussian-package.md)を参照してください。

単体素材では初期の顔位置・身体範囲を素材の範囲から作ります。顔を自動認識する機能ではないため、取り込み後に位置を合わせてください。

状態表示は次のように変わります。

| 表示 | 行っている処理 |
|---|---|
| 素材を検証して取り込んでいます | サーバーが形式、参照ファイル、容量を検査して保存 |
| 素材を読み込んでいます | プレビュー用の素材をローカルサーバーから取得 |
| 表示の細かさを調整するデータを準備しています | SparkがデコードとLoD階層の生成を実行 |
| 利用可能です | プレビューの準備完了。「適用」が可能 |
| 素材を表示できません | 読み込みに失敗。素材とエラー内容を確認 |

映像ページで素材の取得や表示に失敗した参加者は、Discordアイコンへ戻ります。他の参加者の表示は継続します。素材を選び直すと再度読み込みます。

## 顔の位置、大きさ、向きを合わせる

最初に「素材の座標系と正規化」、次に「顔の位置と構図の範囲」、最後に席での倍率と位置を調整します。GSと代理メッシュには同じ変換を適用するため、両方を同じ座標系で作成してください。

| 設定 | 用途 |
|---|---|
| 素材の単位・上方向・正面方向 | 素材の座標系をメートル、Y上向き、Z正面へ変換 |
| 正規化の倍率・回転・位置 | 素材全体の基準姿勢と寸法を調整 |
| 顔の位置 | 正規化後の顔の中心。席とカメラがこの位置を基準にする |
| 顔の範囲 | 顔を囲む3Dの最小・最大座標。カメラの顔の収まりに使う |
| 身体の範囲 | 人物が占める範囲。席間隔と身体の寸法検査に使う |
| 撮影範囲 | カメラに収める範囲。顔の範囲を含める |
| 倍率・向き・横／縦／前後位置 | 顔の位置を基準とした参加者ごとの調整 |

範囲と顔の位置は、正規化後のメートル単位です。素材の座標系を変更しても、入力済みの範囲は自動では書き換えません。各軸の最小値を最大値より小さくし、顔の位置を顔の範囲内に入れてください。顔の範囲は身体と撮影範囲の両方に含めます。

倍率は0.25〜3、横・縦・前後位置はそれぞれ−0.5〜0.5mです。倍率は全方向に同じ値を使います。3DGSの身体は席の向きに固定され、カメラへ正面を向け続けません。口や骨格は動かしません。発話時はGaussianの向きに応じたFresnel発光と弱い外側グローを表示します。3DGS用の発話リングは表示しません。鼻や服の境目も光るため、外周だけの輪郭線ではありません。「発話グロー」の倍率で外側の広がりを調整できます。法線がほぼ正面を向く人物PLYでも、先行発光層が外周を光らせます。細部はGaussianの密度・透明度によって変わります。[発話グローの仕様と検証](gaussian-speech-glow.md)を参照してください。

## 影と反射を付ける

代理メッシュなしのSPZ/3DGS PLYでも、3DGS本体から反射用の深度・法線と影を描画できます。proxy.glbを指定した素材では、これまでどおり代理メッシュを使います。人物の色はどちらも3DGSから描画します。

- 影を確認するには、Dockの「画質」で「影」を有効にします。DirectionalLightまたはSpotLightと、影を受ける机・床が必要です。
- 反射を確認するには、「画面内の反射（SSR）」を有効にし、反射を受ける机や床を映します。画面外の人物など、SSR固有の制約は残ります。
- 代理メッシュがない場合、「3DGSの影・反射形状の不透明度閾値」で薄い部分の扱いを調整できます。既定値は0.3、範囲は0.01〜0.99です。小さい値は薄い部分を残し、大きい値は薄い部分を除きます。カラー表示には影響しません。
- 人物をポストエフェクトに含めると、3DGSまたはproxyから得た深度をDoFへ渡します。

この直接描画はSplatごとの不透明度を閾値で区切る近似です。細い髪や半透明の積層が欠けたり、浮遊Gaussianが影に出たりする場合があります。元Splat数を使うため、カラーのLoD予算を下げても影・深度・法線の処理数は減りません。重い場合は影灯数、影解像度、SSRを調整するか、軽いproxyを指定してください。[方式と実GPU測定](gaussian-native-geometry.md)に条件と制約を記録しています。

GSは素材に記録された外観を表示します。通常の物理マテリアルのように照明を当て直す処理は行いません。環境の自動露出から人物の色を保護し、ポストエフェクトの人物除外設定に従います。

## 描画量を調整する

Dockの「画質」にある「3DGS全体の描画量（Splat数）」で、全員に使うLoDの目安を設定します。既定値は500,000、設定範囲は1,000〜8,000,000です。左右分割時は全体の値を左右へ配分します。各画面が全体の値を独占する設定ではありません。

LoDは距離と予算に合わせて描画に使うGaussianを選ぶ仕組みです。元データを小さくする処理ではありません。描画量を下げても、読み込んだ元データとLoD階層のメモリは残ります。メモリが不足する場合は、元の素材のSplat数を減らしてから取り込んでください。

ブラウザの開発者ツールを映像ページで開き、次を実行すると診断値を取得できます。

```js
window.entakuGaussianDiagnostics()
```

| 診断値 | 意味 |
|---|---|
| `instances` | 表示用のGSインスタンス数 |
| `assets[].inputSplats` | 素材の元Splat数 |
| `assets[].originalCpuBytes` / `lodCpuBytes` | 公開APIから数えられる元データ／LoD配列のCPUメモリ量 |
| `assets[].sourceBytes` | GS本体と主proxyファイルの取得バイト数 |
| `assets[].loadMs` | GS本体と主proxyファイルのHTTP取得時間 |
| `assets[].decodeAndLodMs` | 取得後の素材準備時間。GSのデコード・LoD生成とproxyの準備を並行実行 |
| `views[].selectedSplats` / `budget` | 視点ごとの選択Splat数と予算 |
| `views[].active` | 現在のフレームで使われた視点かどうか |
| `gpuBytes` / `lodBuildPeakBytes` | 取得できないため`null` |

現在の計測では、GSのデコードとLoD生成を分けて測っていません。proxy付きの`decodeAndLodMs`は、proxyの依存ファイル取得・デコード・形状検査が終わるまでの時間も含みます。LoD単独の所要時間は取得していません。

`sourceBytes`には、主GLB内の埋め込みデータを含みます。後から取得するproxyの外部buffer・texture、manifest、preview、decoderのJS／WASMは加算しません。上のCPU値は公開配列のバイト数で、プロセス全体やGPUメモリ、生成時の最大値は測っていません。

## 保存と持ち運び

「適用」すると参加者の設定を保存します。同じデータディレクトリで再起動すると、参加者と素材の対応を読み戻します。既存の設定プリセットにもGS設定を保存できます。プリセットJSONは素材本体を含まないため、別PCへ移す場合は素材も必要です。

1. エディタで見た目と位置を調整します。
2. 「キャラクターをZIPへ書き出す」を押します。未適用の調整内容も書き出しへ含めます。
3. 別の参加者のエディタで、そのZIPを取り込みます。
4. プレビューを確認して「適用」を押します。

ZIPには素材、正規化、顔と各範囲、倍率・位置・向きを含めます。DiscordのユーザーIDは含めません。同じキャラクターを別の参加者へ割り当てられます。「Discordアイコンへ戻す」は参加者との対応を解除し、保存済みの素材は残します。

旧版の2Dプロフィールとプリセットは読み込みを維持します。新しいGS設定を保存したデータを旧版アプリで開く互換性は保証しません。アプリを戻す場合は、更新前にバックアップしたデータを使用してください。

## エラーを切り分ける

| 症状・表示 | 確認すること |
|---|---|
| 通常の点群PLYと表示される | 3DGS用の回転・縮尺・不透明度を持つPLYか。拡張子だけ変更しても使えない |
| 顔や身体の範囲を保存できない | 各範囲の最小・最大、顔の包含関係、正規化後の単位を確認 |
| GSと影がずれる | GSと代理メッシュが同じ元座標系か。モデル内部の変換も確認 |
| 影が出ない | ライト、影の設定、影を受ける面を確認。proxyなしの場合は不透明度閾値を下げて比較 |
| 読み込みで失敗する | ZIPの参照ファイル、SPZ版、PLY形式、素材のサイズを確認し、同梱サンプルで切り分ける |
| 描画が重い | 描画量、描画解像度、SSR、影の灯数を下げる。メモリ不足なら元データを減らす |
| ブラウザでは動きOBSでは出ない | OBSのブラウザソースを再読み込みし、同じURL・寸法・画質で比較する。[実機確認手順](gaussian-validation.md#実gpuとobsでの確認手順)に記録する |

容量制限の詳細、未実施の確認と再現方法は[パッケージ仕様](gaussian-package.md)と[検証記録](gaussian-validation.md)にあります。
