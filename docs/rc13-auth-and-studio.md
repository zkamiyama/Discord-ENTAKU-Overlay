# 認可中の接続とスタジオ材質の修正（RC.13）

## 認可中にウィンドウが閉じた扱いになる問題

IPCのPING本文を、引用符のないUUIDからJSON文字列へ修正しました。受信側が制御フレームの本文をJSONとして検査する場合、従来のPINGは不正です。認可待機中にも5秒ごとに送られるため、接続を切られる原因になり得ます。

厳密にJSONを検査する模擬IPCで、複数回のPINGを挟んでもAUTHORIZEが完了することを確認しました。利用者が見たエラーの唯一の原因だと確定したわけではありません。実Discordが起動していない検証環境では、認可の完了を確認できていません。

通信断とハートビート失敗を、利用者による認可拒否へ変換しないようにしました。切断理由は数値コードのみ保持します。要求権限はrpcとrpc.voice.readのままで、アプリID、トークン交換先、明示同意は変更していません。

### 安全な接続診断

PowerShellで次のように起動できます。

```powershell
$env:ENTAKU_RPC_TRACE = "1"
bun run start --live --compat-auth --accept-streamkit-compat
```

出力はコマンド名、処理段階、経過ミリ秒、固定のエラー名と数値RPCコードだけです。引数、トークン、認可コード、生の認証レスポンス、参加者名、メッセージ本文は含めません。診断を無効にするには環境変数を削除します。

```powershell
Remove-Item Env:ENTAKU_RPC_TRACE
```

VCチャットの実受信は別の検証です。認可やSUBSCRIBEが成功しただけでは、別アカウントの新規投稿を受信した成功とは扱いません。

## ロゴの黒化

添付ZIPを解析すると、ロゴはKHR_materials_unlit、alphaMode BLEND、白のbaseColorFactorと外部RGBA画像を使っていました。GLTFLoaderが作るMeshBasicMaterialをHDR世界全体と一緒に露出補正していたため、低露出ではロゴの色も暗くなります。

インポートしたunlit素材をスタジオ専用レイヤーへ分け、自動測光と世界の露出・AgXの対象から外しました。露出の適用後に深度を使って合成し、その後でスタジオの色調整・Bloom・DoFを掛けます。アバター除外の設定とは独立しています。PBR材質、GLBのライト値、元ファイルは変更しません。

画素試験では露出1と0.00255のロゴ色が一致し、スタジオを無彩色にしても除外中のアバター色が変わらないことを確認しました。表示の透過と深度の扱いはGLTFLoaderの材質設定を維持します。unlit素材はAO・SSR・SSGIの世界側パスには含めません。

## アルファ境界のPCF影

MASKはThree.js標準のalphaTestをそのまま使います。BLENDの透過材質には、影だけに使うカットアウト判定を追加しました。MeshDepthMaterialとMeshDistanceMaterialに元のテクスチャ・UVを引き継ぎ、onBeforeShadowで影のしきい値を0.5にします。

見た目のalphaTest、透過ブレンド、depthWriteは書き換えません。表示の滑らかな縁を保ちながら、透明部分が長方形の影を落とすことを防ぎます。半透明の影や色ガラスを物理的に再現する処理ではなく、影は二値の輪郭近似です。既存の独自深度材質は上書きせず、追加したGPU資源は素材破棄時に解放します。

## 検証と更新

型検査、単体・結合184件、ローカルChromiumのブラウザ試験43件が成功しました。低露出のunlit色、人物除外、BLEND/MASKの影、既存のSSR、DoF、左右分割、透過、机による遮蔽を含みます。CI結果は配布対象コミットで確認してください。

添付ZIP全体の描画は、この実行環境ではWebGLコンテキストを作れず未確認です。ZIP内の材質・画像・参照は解析しましたが、同条件の画素試験を実スタジオのスクリーンショット確認の代わりとしては扱いません。実Discord認可とOBS実GPUも未確認です。

アプリを終了し、dataをバックアップしてexeを入れ替え、OBSのブラウザソースとDockを再読み込みしてください。既存の素材を再インポートしたり、ライトやGLBを書き直したりする必要はありません。
