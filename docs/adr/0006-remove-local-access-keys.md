# ADR-0006: ローカル表示・操作のアクセスキーを廃止する

- 状態: 採用
- 決定日: 2026-11-06
- 対象: OBSのブラウザソース、Dock、ローカルHTTP／WebSocket
- 以前の決定: ADR-0001のローカル読取キー・操作キーを置き換える

## 背景

今回のアプリは、Discordデスクトップクライアントと同じPCで動かすOBS用ローカルツールである。利用者は、ローカルの別プロセスを悪意あるものとして防御することを対象外とし、設定URLからキーを取り除くことを希望した。従来の`#key=...`、読取・操作ロール、`data/access-keys.json`は設定と診断を複雑にしていた。

## 決定

- `http://127.0.0.1:31337/overlay`と`http://127.0.0.1:31337/dock`を固定URLとする。ポート変更には追従する。
- ローカル独自の読取キーと操作キーを廃止する。WebSocketの`auth`メッセージと認証待機タイマーも削除する。
- WebSocketが確立したら`hello`と状態スナップショットを送る。Dockの操作API、スタジオ・画像API、診断APIはローカルクライアントからキーなしで利用する。
- ブラウザのセッションストレージにキーを保存しない。`data/access-keys.json`は参照・新規作成しない。古いファイルは自動削除せず、そのまま未使用とする。
- `Bun.serve`を`127.0.0.1`に束縛し、Hostの完全一致検査を維持する。状態を変更するHTTPリクエストとWebSocket接続では、同一Originを要求する。これらは別のローカルプロセスに対する認証を意図しない。
- `expectedRevision`・`requestId`による編集競合・二重送信防止、負荷制限、画像とスタジオのサイズ制限は引き続き適用する。
- **DiscordへのOAuth/RPC認可はローカルのアクセスキーとは別**であり、ライブ接続時の利用者同意と読取スコープは変更しない。

## トレードオフ

同じPC上の別プロセスは、ローカルURL経由で参加者情報の取得・設定変更を行える。これは今回の利用条件で明示的に許容する。ブラウザで開いた外部Webサイトからの書き込みやWebSocket接続は、Host／Origin検査で引き続き拒否する。ただし、それをローカルプロセスに対する完全な隔離と説明しない。

## 移行と検証

旧版からのアップデートではOBSのURL末尾の`#key=...`を削除する。既存の設定・席予約・スタジオ素材は変更しない。新しい`access-keys.json`は生成しない。

CIでキー不要のDock・Overlay、WebSocket初期接続、ローカルAPI、別Originからの操作拒否、Bun単独exeの起動を確認する。DiscordとOBSの実機受け入れ試験は引き続き別扱いとする。

## カメラ遷移の同時改善

同じ変更版で、近い会話ペアへ移るSINGLE→TWO_SHOTとその逆の遷移は、現行のカメラ補間を利用してMOVEにする。モデルの障害物経路検査は引き続き優先し、危険な移動はCUTへ戻す。
