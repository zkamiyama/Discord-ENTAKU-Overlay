# ADR-0002: 初回の開発版をデモと接続基盤に分ける

- 状態: 採用（開発版の段階的実装）。最終仕様の機能を削除する決定ではない。
- 決定日: 2026-11-06

## 背景

本番の発話状態にはDiscordの認可と実通話が必要になる。一方、席予約とカメラ判断は、同じ形のイベントを再生すれば独立して検証できる。実機認可を未確認のまま、UIや配布を完成扱いにはしない。

## 決定

引数なしの起動はデモにする。ライブ接続は明示的な互換認証フラグと同意フラグを要求する。`--doctor`は既定でオフラインとし、アプリIDを指定したときだけローカルIPCハンドシェイクを行う。音声情報の認可はdoctorに含めない。

初回のWebプロトコルは、同一Originのローカルクライアントへの全状態スナップショットとする。定期送信は約10Hz、発話などの入力時には追加で送信する。serverEpochとseqを付け、操作にはexpectedRevisionとrequestIdを要求する。差分配信・詳細なイベント再生UIは後続とし、この段階で長期のプロトコル互換性を保証しない。

初期の人物表示はDiscordの円形アイコンと代替アイコンに限定する。発話リングは円の輪郭に沿わせる。任意の画像のアルファ境界グロー、顔矩形のGUI、カスタムGLB、シーン編集、インポートした障害物によるカメラ制約は最終仕様どおり後続に残す。円形リングをSDFグローの完成実装とは呼ばない。

カメラのワイドは標準アバターの範囲をカメラ空間へ投影して算出する。SINGLEは顔と名前プレートを収めるため、注視点を標準顔アンカーより0.12m下げる。素材別のフレーミングは顔矩形GUIの段階で拡張する。

初回ZIPは開発用アーティファクトとする。公開の安定版タグやリリースは作成しない。ライブDiscord、OBS本体、長時間稼働、性能、署名、認証利用条件、配布物のライセンス確認をリリース条件として分けて記録する。

## 影響

取得経路を待たずにデモとReplayを検証できる。Web配信の差分処理を後回しにするため、参加者数の多い場合の通信量は今後測定する。全状態を毎回送る簡易実装を、そのまま最終的な性能保証とはしない。
