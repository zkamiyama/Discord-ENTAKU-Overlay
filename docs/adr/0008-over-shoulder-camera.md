# ADR-0008: 対向席の肩越しカメラと可視性判定

- 状態: 採用。実装・検証は別途記録する。
- 決定日: 2026-11-06
- 関連: ADR-0007、利用者の肩越し撮影の指定

## 決定

単独話者の標準構図は、在席している対向席の頭・肩越しとする。注視点は話者の顔であり、机の中心ではない。奥の司会席は専用の構図名を持つ。左右の同じ列で向かい合う2人もTWO_SHOTの候補とする。

カメラ候補を左右と高さを変えて調べ、話者の顔と名前プレートを遮る人物がいない候補を採用する。前景として使う人物も遮蔽検査から除外しない。見やすい肩越しが得られない場合は、横へ移す、上げる、通常の単独構図へ戻す順に対処する。人物を透明にして遮蔽を隠す処理は行わない。

既存の画像寸法、顔矩形、倍率、位置、独立した背面画像から人物の占有範囲を求める。撮影範囲を狭めても、画面に描かれる人物の占有範囲は小さくしない。Y軸±30度の追従も含めた保守的な範囲を使う。透過画像の各ピクセルを判定する処理ではないため、透明な余白を含む画像では必要以上に高い構図や通常構図になる場合がある。

SINGLEとTWO_SHOTの移行は既存のMOVEを維持する。直線移動が人物を横切る場合は、高さを加えた曲線移動を試す。安全な経路が見つからない場合だけCUTにする。カスタムスタジオの障害物制約は引き続き適用する。

## 既存APIの利用

人物の近似範囲と交差判定にはThree.jsのBox3、Matrix4、Rayを使う。画角の確認にはPerspectiveCameraとVector3.projectを使う。曲線移動にはQuadraticBezierCurve3、時間補間にはMathUtils.smootherstepを使う。独自のレイ交差アルゴリズムやモデルローダーは作らない。

座席ロール、候補の選び方、顔と名札を優先する規則はアプリ固有の処理である。Three.jsのRaycasterはメッシュの交差を求めるものであり、通話の誰をどの構図で撮るべきかを決める機能ではない。

## 表示と検証

Dockに構図名、前景席、遮蔽回避の理由、MOVE／CUTを表示する。司会ロールはアプリ内の指定であり、Discordサーバーロールの自動取得とは扱わない。

5・6・7人と司会1〜2人の配置、退出復帰、司会設定の保存、背面を含む大きな画像、対向席の欠席、移動中の遮蔽、スタジオ障害物を回帰試験にする。匿名化した記録では司会者IDも仮名化する。
