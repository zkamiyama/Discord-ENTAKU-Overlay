# ADR 0030: カードの平面メッシュとフレーズ反復の検査

日付: 2026-11-28 JST

状態: `feat/misskey-hashtag-cards`で実装。[ADR 0029](0029-public-hashtag-cards.md)のカード描画と反復判定を変更する。通信、公開範囲、表示件数、削除追従の判断は継続する。

## 課題

Spriteは常に画面と平行になり、空間内で傾いたカードとして見せられない。利用者はカードの幾何形状、カメラアニメーション、SPLITでの表示を求めている。また、単一文字や短い周期の反復を除外する初期実装では、「きたああああああああああああ！」や長い「w」も表示されない。歓声を許可し、ある程度の長さと文字の種類を持つフレーズの過剰な繰り返しを除外したい。

## 決定

### 共有する平面メッシュ

Three.js 0.187.0の標準`Mesh`、`PlaneGeometry`、`MeshBasicMaterial`、`CanvasTexture`を使う。`MisskeyCards`が1個の`PlaneGeometry(1,1)`を所有し、最大30スロットで共有する。文字は既存の512×256テクスチャへ描き、テキスト自体のポリゴン化は行わない。本文やフォントが変わる場合だけCanvasを更新する。

傾きはスロットごとの固定seedと小さな時間変化から作る。XYZ各軸の角度の絶対値は、揺れを含めてXが7.5〜15.5度、Yが13〜22度、Zが2〜7度になる。どのカードも真正面には戻らず、文字を読める程度の傾きを保つ。

### 各ビューでの姿勢

`Object3D.onBeforeRender`が受け取る実際のカメラから、描画の直前にカードの向きを求める。中心は空間内のスロットに置き、面はカメラへ向く姿勢に固有の傾きを加える。カメラが移動・回転しても追従し、SPLITの左右ではそれぞれのカメラへ向く。前のビューの姿勢や補間状態は入力に使わない。

カメラの上方向はworld matrixから取り出し、rollも反映する。stageの移動・回転・非一様scaleを考慮し、worldの直交する基底から面の姿勢を作る。親の逆行列を掛けたlocal matrixはそのまま保持する。decomposeすると非一様scaleを打ち消すためのshearが失われるためである。

r187では視錐台カリングと透明物体のソートがcallbackより前に行われ、modelViewMatrixの計算はcallbackの後に行われる。古いビューの傾きでカリングされないようカードの`frustumCulled`をfalseにする。対象は最大30枚で、画角外はGPU側でクリップする。ソート用の中心は`prepare`で先に更新し、callbackでは動かさない。callback内でmatrixWorldを更新すれば同じdrawへ反映される。

`FrontSide`とし、透明な両面を2回描く処理は使わない。既存の`depthTest=true`、`depthWrite=false`、`renderOrder=-1`、display layer 1を維持する。人物より先にカードを描き、3DGS人物をカードで上書きしない。影、反射、露出計算からも引き続き除外する。

この方式の面はビューごとに回転する。すべてのカメラから同じ固定姿勢の物体を撮る方式ではない。SPLITで各画面の文字を読めることと、傾きによる奥行きの両方を優先した。

### フレーズの過剰反復

単一文字の連続回数による除外を撤去する。全文を静的テキストへ変換して正規化し、監視タグを除いた文字列について、次の条件をすべて満たす連続反復を除外する。長さはgrapheme単位で数える。

| 条件 | 値 |
|---|---:|
| 反復単位の長さ | 5〜64文字 |
| 単位内の異なる文字 | 3種類以上 |
| 連続反復 | 5回以上 |
| 反復区間の長さ | 30文字以上 |
| 正規化した全文に占める反復区間 | 60%以上 |

最短の単位が1〜4文字なら、それを複数まとめて5文字以上の単位として扱わない。「わーいわーい」の6文字が繰り返されても、元の周期は3文字として通す。単一文字、通常の絵文字の連続、短い笑いや応答も反復だけを理由に除外しない。

「加藤純一最強！」を6回続けた例は、この一般規則で除外する。固有名の除外辞書は追加しない。同じ長さ・種類数・回数を満たす別のフレーズにも同じ規則を適用する。

60%以上を占める対象区間は本文中央の比較ペアを通るため、全開始位置を試さず、そのペアを含む連続反復だけを調べる。文字の種類が2種類以下なら早期に通す。MFM処理、NFKCの展開、grapheme分割の費用は残る。本文16,000 UTF-16単位などの入力上限と、1 graphemeが64 UTF-16単位を超える異常入力への保護を維持する。

本文の省略は審査の後に行う。危険語、全文重複、同一投稿者の表示・待機上限、採用間隔は独立して継続する。したがって同じ「w」だけの投稿が既に採用されていれば、後の同一内容は重複で除外される。

## 比較した代替案

| 案 | 判断 |
|---|---|
| Spriteのmaterial.rotation | 画面内の回転はできるが、面の傾きによる遠近を付けられない |
| 固定姿勢のPlaneGeometry | カメラが回り込むと端や裏を向く。今回の読みやすさの要件では各ビューへ向ける |
| main cameraだけでlookAt | SPLITの別カメラへ同じ姿勢が残るため使わない |
| InstancedMesh＋テクスチャアトラス | drawを減らせるが、個別テキスト更新と透明描画の管理が増える。最大30枚では共有PlaneGeometryを測定する |
| 反復した文字の名前による許可リスト | 新しい歓声や絵文字を列挙し続ける必要がある。長さと種類数で判定する |
| 特定の固有名を含むNG辞書 | 利用者が求めるのは過剰なフレーズ反復の抑制であり、通常の言及まで除外する理由はない |

## 検証と限界

単体試験はカメラ移動・roll、SPLITのAB/BA描画順、親を持つカメラ、非一様scale、中心位置、資源共有・解放を検査する。WebGL試験では実描画後の行列と画素を確認し、カメラを動かした場合も面に奥行き差があり、左右の描画順を入れ替えても各画面が一致することを確かめる。既存のOverlay、SPLIT、Spark人物の遮蔽試験も継続する。

反復試験は利用者の例、短い周期の束ね誤認、回数・長さ・種類数・60%の境界、本文内の位置、Unicode、MFM、全文審査と投稿者制限を検査する。短い単位、65文字以上の単位、60%未満の区間はこの規則の対象外である。途中で文字を変えても、前後に条件を満たす連続区間が残れば除外する。意味の理解や荒らしの完全な排除を保証しない。

描画測定の条件と生値は[利用・調査記録](../misskey-hashtag-cards.md)を参照する。実GPU、WindowsのOBS/CEF、長時間の配信は未検証である。
