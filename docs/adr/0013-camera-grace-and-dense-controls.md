# ADR-0013: 自動撮影の猶予、手動撮影の期限、設定の整理

- 状態: 採用。実装と回帰試験の後に配布する。
- 日付: 2026-11-09

## 撮影のタイミング

発話による自動切替は、候補の構図が5秒継続した後に行う。SINGLE、TWO_SHOT、同時発話と無音のWIDEを同じ規則にする。候補が変わった場合は猶予を数え直し、現在の構図に戻った場合は取り消す。切替完了後の最短維持も5秒とし、猶予との二重待機にはしない。通信断と机の再配置に必要な安全退避は即時とする。

自動がONのときの手動撮影は既定10秒でAUTOへ戻す。期限はサーバーの単調時計で管理し、Dockを閉じても進行する。手動の連続操作は期限を更新する。再配置中に予約された手動撮影は、実際に開始した時点から数える。自動をOFFにすれば固定撮影となり、期限は取り消す。独立した構図固定ボタンは廃止する。AUTOへ戻った時点で唐突に構図を変えず、その後の自動判断にも5秒の猶予を使う。

## 構図

ワイドは従来の高さのおよそ30%を基準とし、机より低くならない下限を設ける。人数、人物画像の大きさ、名札を投影して余白付きで収まる距離を決める。単独・2人ショットは画角を狭くし、必要な距離まで後退して望遠寄りの構図にする。肩越しの前景、顔と名札の可視性、スタジオ障害物の判定は維持する。

Three.js r187のPerspectiveCamera、Vector3.project、Ray、Box3を先に確認して利用する。投影行列や交差判定を独自に実装しない。構図候補の順位と切替猶予はアプリ側の責務とする。

## Dockと画質

画質とポストエフェクトを独立したメニューに分け、卓上の設定はスタジオへ移す。数値入力はスライダーと短い数値欄を組み合わせ、プレビューと保存の既存イベントを維持する。数字を直接入力する経路も残す。余白と行高を詰めるが、ラベルとキーボード操作は省かない。

MSAAに2xを追加し、実際に利用するサンプル数はGPUが対応する色・深度フォーマットの組合せから選ぶ。選択値と実効値を区別する。影を作るライト数の上限に8を追加する。8灯が存在しない場合は存在する分だけを使用し、光源を増設しない。標準の4x・2灯は変更しない。

## 検証

仮想時計で切替直前・直後、候補取消、2人から1人、手動期限、固定と復帰を検査する。全席数と大きな画像のフレーム内収まり、肩越しの遮蔽、設定の移行、すべての数値欄のスライダー連動、狭いDockでの表示とキーボード操作を確認する。OBS本体で未確認の性能を、自動テストの成功で代替したとは説明しない。
