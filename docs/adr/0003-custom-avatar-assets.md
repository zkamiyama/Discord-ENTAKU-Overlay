# ADR-0003: カスタム人物画像を素材と調整値に分ける

- 状態: 採用。P4を段階的に実装する。
- 決定日: 2026-11-06

## 背景

Discord IDと画像を対応させても、画像の余白や顔の位置が違うと人物の大きさがそろわない。画像の長方形に沿った輪郭では、透過画像の発話表示にも使えない。これらを円形アイコン用の処理とは分離する。

## 決定

画像はローカルの素材ストアへ取り込み、内容のSHA-256をassetIdにする。クライアントが送ったファイル名やパスを保存先に使わない。取り込みは操作権限と同一Originを必須とし、PNGと静止WebPの形式・寸法・容量を検証する。画像の配信にも読取権限が必要である。

人物の設定はDiscord ID、assetId、顔矩形、倍率、位置調整から構成する。顔矩形は元画像左上原点の正規化座標で保存する。元画像や顔矩形を、描画用の縮小やグロー余白に合わせて書き換えない。顔高の初期値は0.28mである。

Dockでの編集はDraftとし、「適用」するまでは本番へ送らない。保存成功後にサーバーの編集revisionを進める。画像の選択だけで既存の人物を置き換えない。サーバーの保存失敗や編集競合では、以前の設定を保持する。アプリの再起動後も設定を読み込む。セーフモードは素材・調整値をメモリ内だけに保持する。

描画には元画像のアルファから生成した距離マップを使う。距離マップは画像変更時だけ計算し、発話中は強度だけを更新する。本体と柔らかい外側グローを分離し、どちらも机の深度を無視しない。Y軸追従は±30度、裏面は減光し、前後で画像を反転するために人物全体を回転させない。

初回の追加では顔矩形と数値調整を実装し、3Dプレビュー、独立した背面画像、フレーミング矩形の編集は後続に分ける。設定できない項目を保存済み・対応済みとは表示しない。極端に広い素材は現在の席間隔を超えて黙って重ねず、調整を求める。この制限は最終仕様の可変幅配置を削除する決定ではない。

## 検証

不正形式・サイズ超過・アニメーション・範囲外矩形・別Originからの操作を拒否する。顔の座標変換、アルファの穴、画像四辺の余白、設定の保存復元と競合を自動試験する。ブラウザで画像選択、顔矩形の指定、適用、再読み込み、リセットを確認する。OBSでの透過合成と実機GPUの描画は別の受け入れ試験とする。
