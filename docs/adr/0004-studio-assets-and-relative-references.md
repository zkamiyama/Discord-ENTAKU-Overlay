# ADR-0004: スタジオの外部素材は参照形式ごとに管理する

- 状態: 採用（GLB/GLTFの安全な取り込み機能は段階実装）
- 日付: 2026-11-06
- 対象: Studio JSON、GLB、GLTF、テクスチャ、配布ZIP

## 背景

BlenderのglTFエクスポートには、単一GLBと、GLTF・BIN・テクスチャの複数ファイル構成がある。関連ファイルの相対参照を一律に拒否すると、通常のBlender制作を妨げる。以前の「外部参照を拒否する」という方針は広すぎた。

一方、任意のネットワークURLやインポート領域外のパスを無条件に読み込むと、オフライン配布時に素材が失われ、意図しない通信とファイル参照が発生する。

## 決定

- GLB内の埋め込み素材を受け入れる。モデル本体・相対画像・外部バッファ・glTF拡張の解釈にはThree.jsの`GLTFLoader`を使用し、独自の読み込み処理を作らない。
- GLTFの `textures/wood.png` などの相対参照を受け入れ、ファイル一式を取り込み先のスタジオ資産として保管する。
- `data:` URIは画像・バイナリの既知MIME形式に限って受け入れる。
- 取り込み範囲の外へ出る`../`、絶対パス、`file:`、無条件のHTTP(S)取得を禁止する。範囲内に解決できる親フォルダー参照は受け入れる。文字列検査だけでなく、解決後のファイル名と内容も確認する。
- HTTPS参照は将来、明示的な許可とオフライン保存を伴うオプションとして検討する。初期版では自動ダウンロードしない。
- インポートした関連ファイルは内容から識別できるようにし、配布ZIPとバックアップに必要なファイルをまとめられるようにする。
- 入力解析はインポート時のメタデータと依存ファイル一覧・パスの安全性の確認だけに使う。読み込み時は`GLTFLoader`に委ね、必要なら`LoadingManager.setURLModifier()`でローカル資産からBlob URLへマップする。
- インポートの検証が通る前に、本番シーンを変更しない。設定はrevisionと原子的な保存を用いる。
- 外部モデルの描画で発生したエラーは既存の円卓・人物描画を停止させず、Dockに原因コードを表示できるようにする。

## 段階実装

最初にStudio JSONの厳密検証、相対パス解決、GLB/GLTFの参照検査を単体テストする。次に複数ファイルのインポート、保存、ローカル配信を実装する。最後にThree.jsへの配置・Dockからの編集・シーン境界のカメラ制御を導入する。

スタジオモデルを導入しただけで、カメラの衝突回避が完了したと主張しない。任意のGLB障害物に対する撮影経路検証は別の受け入れ条件とする。
