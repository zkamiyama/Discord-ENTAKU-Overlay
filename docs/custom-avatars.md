# カスタム画像の登録と調整

対象は0.1.0-dev.2の初期実装である。映像は`/overlay`、編集は`/dock`で行う。画像はDiscord IDに対応させ、同じ人が退出・復帰しても設定を保持する。

## 操作

人物の「画像を調整」を開き、PNGか静止WebPを選ぶ。画像の顔をドラッグで囲むと、元画像に対する百分率が入力欄へ入る。矩形は数値でも編集できる。顔の高さを0.28mにそろえたうえで、倍率と横・縦位置を調整する。「適用」で保存し、本番表示へ反映する。「キャンセル」では本番設定を変更しない。

初期矩形は便宜的な値であり、顔検出の結果ではない。画像ごとに実際の顔を囲む。髪や帽子の大きさではなく顔でそろえると、人物間の見た目を調整しやすい。

「Discordアイコンへ戻す」は人物への対応付けを解除する。元画像を削除する操作ではない。選択時に取り込んだ画像はキャンセル後も素材ストアへ残る。不要素材の整理GUIは未実装である。

## 保存と編集の保護

画像の保存先は`data/assets/avatars/<SHA-256>`、人物設定は`data/avatars.json`である。ブラウザから渡されたファイル名やパスは保存先に使わない。元画像と顔矩形を、描画時の縮小やグロー用余白に合わせて書き換えない。

編集を開いた時点のrevisionを保存時に照合する。編集中に他の設定操作が入った場合は競合を表示し、上書きしない。閉じて開き直すと現在の設定を取得する。音声イベントの受信だけでは編集revisionを進めない。

保存は一時ファイルを経由し、前の設定を`.bak`に残す。保存に失敗した場合は以前の本番状態を保つ。セーフモードでは素材と設定をメモリ内だけに保持し、通常の保存先を変更しない。

## 現在の制限

画像は20MiB以下、縦横4096px以下とする。アニメーションPNG/WebP、SVG、GIFは拒否する。PNGのコンテナーとCRC、WebPのコンテナー、寸法をサーバーで検査し、画像デコードはブラウザで行う。不透明度が128/255以上の部分がない画像は登録画面で拒否する。

現在の机は既定の席間隔を使う。顔を中心に見た左右の最大張り出しと横調整から占有幅を計算し、0.98mを超える設定は保存しない。単なる画像幅だけでは、顔が片側に寄った画像同士の重なりを防げないためである。画像に合わせて席間隔を拡大する処理は後続の実装とする。

倍率は0.25〜3、位置調整は±0.5mだが、占有幅や高さの検査を満たす必要がある。人物の全高は4m以内、上端は床から3m以内とする。床より下の画像部分は描画しない。

素材ストアは最大256画像、ディスク保存では合計512MiB、メモリ保存では128MiBまでとする。同一内容の画像は同じassetIdになる。画像を繰り返し選択して上限に達した場合、保存容量を無視して続行しない。

## 描画と未対応項目

顔中心を回転の基準にし、Y軸だけ±30度までカメラへ向ける。背面からは正面画像を暗く表示するため、背面の図柄は鏡像になる。独立した背面画像は未対応である。

画像のアルファから距離マップを作り、発話時は外周と透明な穴の境界に緑色を表示する。距離マップは画像変更時にだけ作成する。発話イベントで毎フレーム作り直さない。元画像が大きい場合、描画用画像は長辺1024pxへ縮小し、周囲に余白を追加する。

現在の編集プレビューは2Dである。3Dプレビュー、独立したフレーミング矩形、素材の整理GUI、任意GLBスタジオ、実機GPUでの性能保証は未対応または未検証である。最終仕様のこれらの項目を削除したわけではない。
