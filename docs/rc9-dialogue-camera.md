# 会話に合わせたカメラ（RC.9）

## 発話の開始と終了で待機を分ける

| 場面 | 判定 |
|---|---|
| 話し始め | 合計2.5秒の実発話で切替対象になる |
| 2人構図の片方が話し終わる | その人のSTOPから5秒待って、残る話者へ絞る |
| 全員が無音になる | 最後のSTOPから5秒待ってワイドへ戻る |
| 待機中に再発話する | 終了待ちを取り消し、現在の構図を維持する |
| 手動撮影 | 発話の待機を通さず切り替える。机の再配置中だけ撮影を予約する |

内部の1秒の資格判定に、さらに2.5秒を足す動作ではありません。短い無音を挟んで発話をつなぐときも、無音時間は加算しません。カメラ移動中や最短維持時間、主話者の比較で切替が遅れる場合はあります。

新しい話者への交代は開始側の2.5秒で判断し、終了側の5秒を重ねて待ちません。通信断と席の再配置は、安全なワイドを即時に優先します。

## 直近10秒の発話量で主話者を選ぶ

利用者ごとに、直近10秒と重なる実際の発話区間を積算します。10秒より古い部分は除き、無音や不明状態を足しません。同時に話した時間は、それぞれの利用者へ計上します。声の大きさや最後に喋り始めた順番では決めません。

短い相槌だけでは撮影対象を変更しません。2人の発話量が拮抗している場合は、安全に収まる2人構図を使います。一方の発話量が他方の1.6倍以上、かつ差が1秒以上ある場合は、その人の単独構図を優先します。会話の途中で主役が変わるときは、候補が2.5秒安定することも確認し、小さな差で往復しないようにします。

これは発話時間に基づく撮影上の近似です。話の内容や相槌の意味を音声解析する機能ではありません。「カメラの判断」に主話者と直近10秒の発話量を表示します。

## 正面軸のワイドと司会後方の禁止

ワイドは司会席正面の軸に固定します。人数やアバターサイズに合わせ、人物・名札・天板が左右上下に約5%の余白を残して入る最短距離を求めます。旧版の約30%の高さを基準とし、必要な場合だけ高さを最大0.75m補正します。左右へ回って重なりを避けることはしません。

司会側の天板後端より後ろへ、カメラを置かないようにしました。肩越し、2人構図、移動経路、指定された退避ワイドにも同じ制限を使います。狭い画角と遮蔽物の組合せで構図を作れないときは、後方へ回り込まず正面ワイドへ退避します。

正面・低位置では、手前の人物と奥の人物が一部重なる場合があります。フレーム内への収容と、全員の顔が完全に隠れないことは別です。カスタム画像の透明部分を画素単位で判定する機能はありません。

人物撮影は引き続き縦22度、2人構図は通常26度です。「カメラ設定」で人物の画角を調整できます。司会後方を使えなくなった対面2人構図では、手前側から高さを補正する場合があります。

## ニアクリップ

「カメラ設定」にニアクリップを追加しました。既定は0.15m、設定範囲は0.02〜1mです。カメラの手前側でこの距離より近い部分を描画しません。Three.js標準のPerspectiveCamera.nearを使い、設定変更時に投影行列も更新します。主被写体のフレーム判定には同じ値を使います。

大きくしすぎると前景の人物や机も切れるため、まず既定値で確認してください。ニアクリップは、カメラの前にある遠い壁を消す機能ではありません。

## 手動撮影とDock

自動ONで「この人を撮る」またはワイドを押すと、既定10秒でAUTOへ戻ります。残り時間はサーバーで管理し、Dockを再読み込みしても期限を延ばしません。再度の手動撮影で期限を更新します。自動OFFでは時間制限なしの固定になります。

Dockには全数値欄のスライダー、独立した「画質」と「ポストエフェクト」、スタジオ内の「卓上」を用意しています。MSAA 2xと影の最大8灯も選択できます。GPUが2xを提供せず4xだけに対応する場合、実効値は4xです。影8灯は平行光源・スポットライトが対象で、標準は2灯です。

## 更新と確認範囲

アプリを終了し、dataフォルダーをバックアップしてから新しいexeへ入れ替えます。URLと保存済み素材は引き継げます。OBSのソースとDockを再読み込みしてください。

境界時刻、再発話、相槌、10秒窓、正面軸、後方禁止、近クリップ、手動期限、設定復元を自動試験します。実Discord通話やOBS実GPUでの長時間運転・フレームレート・ユーザーのGLBの見通しは、この試験とは別です。
