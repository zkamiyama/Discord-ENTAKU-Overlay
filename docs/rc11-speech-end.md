# 言い淀みと発話終了の判定（RC.11）

## 変更した動作

DiscordのSTOPを受けても、すぐには会話上の発話終了と判定しません。無音が2.5秒続くまでは終了確認中とし、途中でSTARTが来れば同じ発話ターンを再開します。既に満たした撮影資格と実発話時間は引き継ぎ、再開するたびに最初から2.5秒を数え直すことはありません。

無音が2.5秒続いたら終了を確定し、そこから構図変更まで5秒待ちます。終了だけを理由に構図を縮めたりワイドへ戻したりする場合、最後のSTOPから最短7.5秒です。これはRC.9・RC.10の「STOPから5秒」を置き換える規則です。

| 最後のSTOPからの時間 | 撮影側の状態 | Dockの表示 |
|---|---|---|
| 0〜2.5秒未満 | 終了を未確定のまま構図を保持 | 終了確認 |
| 2.5秒 | 発話終了を確定。構図変更の5秒猶予を開始 | 切替まで 5.0秒 |
| 2.5〜7.5秒未満 | 再発話を待って構図を保持 | 切替まで |
| 7.5秒以降 | 残る話者へ絞る。全員無音ならワイドへ戻る | 自動撮影中 |

どちらの待機中でも再発話すれば、終了待ちを取り消します。2.5秒未満の休止なら同じ発話ターン、終了確認後なら新しい発話ターンです。終了確認後に再発話しても、資格判定中の人物を現在の2人構図や分割から即座に外しません。

新しい話者の開始判定は実発話2.5秒のままです。上の7.5秒は終了だけを理由に構図を変える場合の待機であり、別の話者への切替を一律に7.5秒遅らせる規則ではありません。会話の主導権、画角の安全性、カメラの最短維持時間も引き続き判定します。手動操作は即時、通信断や机の再配置は安全な全景を優先します。

## 計測値は変えない

発話グローと参加者一覧の発話状態は、生のSTART/STOPに追従します。画面上で話していない人を2.5秒間光らせ続ける変更ではありません。直近10秒の発話量、重なり、交代の集計にも無音を加えません。例えば4秒話して2秒休んだ場合、発話量は4秒です。

短い相槌が、無音待機だけで長い発話になることはありません。重複STOPも終了確認の期限を延ばしません。不明状態や接続断では、保持していた発話ターンを破棄します。

## 2人構図・左右分割・3人目

通常の2人構図、左右分割、3人以上の全景から絞る場面に同じ終了確認を使います。3人目へ発言が移り、元の2人が別々の時刻に止まった場合は、最後に止まった側の終了確認から5秒待ちます。途中で誰かが再開すれば終了待ちを取り消します。

左右分割の開始条件、10秒の発話量による主話者選択、再分割までの待機、司会正面のワイド、望遠撮影、手動操作の10秒後の自動復帰は維持します。設定・画像・スタジオを変更する必要はありません。

## 更新と確認範囲

アプリを終了してdataフォルダーをバックアップし、新しいexeへ入れ替えます。OBSのブラウザソースとDockを再読み込みしてください。URLは同じです。

境界時刻、再発話、実発話時間、重複STOP、不明状態、短い相槌、複数話者の終了時刻、Dockの二段階のカウントダウンを試験します。言い淀みの意味を音声から認識する機能ではなく、無音の長さで扱いを分ける規則です。実Discord通話とOBS実GPUの長時間運転は自動試験と別に確認が必要です。
