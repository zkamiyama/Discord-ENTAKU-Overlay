# 開発状況

更新日: 2026-11-06。対象: 0.1.0-dev.2。仕様・実装・検証を区別する。

## 現在の到達点

ADRを先にmainへpushし、IPC、席、カメラ、状態ストア、Replay、サーバー、UI、配布を別コミットで実装した。操作画面名はDock、ルートは`/dock`である。今回の追加判断はADR-0003に記録した。

単体・結合テスト68件がローカルで成功している。100回の退出・復帰、チャンネル別の席保存と再起動、保存失敗後の復旧、認証・編集競合、画像の形式と寸法、顔座標の変換、距離マップ、カメラの画角を含む。これらは仮想イベント・テスト用素材での検証であり、Discord通話の実地試験ではない。

ChromiumのE2Eは4件である。Dockの発話操作、SINGLEへの切替、席の保持と復帰、Dock再読み込み、未認証の遮断に加え、PNGのDraft・適用・設定再読込・解除と、360px幅のDockでの静止WebP登録・矩形ドラッグを確認した。カスタム画像は合成したテスト用マスクを使い、外側と内部の透過部分に輪郭が出ることを確認した。

Windowsで生成される`.bun-cache/`を追跡対象から除外し、単独実行ファイルの試験終了後に生じる一時ファイルのロックには、終了待機と回数制限付きの削除再試行を加えた。修正後のWindows/Linux CIでは、空のPATHと実行ファイルだけの一時フォルダーでHTTP・埋め込みWeb素材を検証し、Windows ZIPの作成も成功している。配布物の版ごとの結果は対応するGitHub Actionsの実行記録で確認する。

日本語UIはOSフォントを利用する。日本語フォントを持たないLinuxテスト環境では字形が欠ける。フォントファイルは配布しない。Windows/OBS本体での日本語表示は受け入れ試験に残す。

## 追加した機能と修正

再起動後に参加者名がまだ取れていない予約席も、DockにDiscord IDとともに表示する。接続状態が不明な間は予約を解放しない。デモ参加者の追加も、保存済みの予約IDを再利用しない。

カスタム画像は内容ハッシュで保存し、画像と顔矩形・倍率・位置を分離する。設定の保存に成功してから本番状態を更新し、保存失敗や編集競合では以前の状態を保つ。サーバーは画像のコンテナーと寸法を検査し、ブラウザでデコードする。デコードに失敗した画像を正常とみなさない。

カメラはカスタム画像の範囲と、人物より手前にある名前プレートを画角へ収める。机の伸長や画像更新によるワイド待機中に手動ショットを指定した場合、その指定を捨てず、待機終了後に実行する。AUTOへ戻すと待機中の手動指定を取り消す。

## 既知の制限

標準シーンだけをサポートする。カメラのMOVE検査は既定の机と人物方向に限定し、任意のGLB障害物を避ける機能ではない。カスタム画像は顔を中心とした占有幅0.98m以内で、画像の大きさに合わせて席間隔を拡大する機能はまだない。距離マップは画像変更時に最大1024pxへ縮小したマスクから計算する。生成処理のWorker移行と実機でのフレーム時間測定は未実施である。

背面は正面画像を減光して表示する。独立した背面画像や左右反転なしの背面表現はまだない。シーン設定GUI、詳細イベントログのエクスポート、ReplayのシークUIも未実装である。

ライブの参加者メタデータ再同期は15秒ごと、入退室後は追加照合する。GET_CHANNELに発話中フラグがあるとは仮定しない。取得経路が途切れたときはunknownに戻し、長い発話を任意TTLで切断しない。

実Discord・OBS・2時間連続運転・16人1080p60fps・署名は未検証または未実施である。自動テストの成功で代替しない。GitHub Actionsの失敗があれば、その失敗を優先して修正する。
